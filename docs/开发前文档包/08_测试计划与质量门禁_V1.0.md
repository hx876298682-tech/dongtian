# 《洞天》MVP 测试计划与质量门禁 V1.0

## 1. 质量目标

项目最不能出错的不是动画，而是时间与资产。测试优先级：

1. 不重、不漏、不负：奖励、消耗、机会和突破绝不重复、丢失或变负。
2. 同输入同结果：在线 / 离线、首次请求 / 重试、崩溃前 / 恢复后结果一致。
3. 可解释：玩家能看到行动为什么切换、停止或产出不同。
4. 可回滚：配置和代码发布失败不会破坏历史资产。
5. 好理解：新玩家能掌握规划—回流—再规划循环。

## 2. 测试层级

| 层级 | 目标 | 主要覆盖 |
|---|---|---|
| 单元测试 | 验证纯规则 | 时间、周期、修正、XP、战斗、掉落、税费 |
| 属性 / 模糊测试 | 验证不变量 | 非负库存、单调时间、幂等、批量与逐次等价 |
| 数据库集成 | 验证事务 | 锁、回滚、账本、Outbox、版本冲突 |
| API 契约 | 前后端一致 | Schema、错误码、兼容、幂等重放 |
| 端到端 | 验证用户链路 | 登录到再次闭关完整垂直切片 |
| 配置校验 | 防止内容错误 | 引用、概率、可达性、套利、解锁来源 |
| 性能 / 稳定性 | 验证容量 | 登录结算峰值、锁等待、长离线、重启 |
| 可用性 | 验证产品假设 | 理解、规划、目标清晰、秘境价值 |

## 3. 测试环境与数据

- `test`：每次提交自动化，固定种子和可重置数据库。
- `staging`：与生产拓扑一致，使用脱敏或合成账号。
- `production`：只做只读健康检查和受控小额合成探针，不造玩家资产。

黄金角色：

| ID | 状态 | 用途 |
|---|---|---|
| G-001 | 新账号 / 凡人 | 教程与首轮队列 |
| G-002 | 炼气初期 / 2 槽 | 离线和炼丹 |
| G-003 | 炼气后期 / 材料不足 | 阻塞与保底 |
| G-004 | 炼气大圆满 / 筑基差一项 | 目标追踪 |
| G-005 | 筑基初期 / 3 槽 | 条件队列 |
| G-006 | 秘境入场前 | 幂等与断线 |
| G-007 | 经济高库存 | 溢出、资产消耗、64 位边界 |

每个黄金角色保存：数据库种子、配置版本、预期结果和账本校验值。

## 4. 核心规则单元测试

### 时间与周期

- 0、1 微秒、恰好一个周期、一个周期减 1 微秒、多个周期加尾数。
- `action.cultivation.qi` 固定 60 秒周期、4.5 修为；1 / 8 / 10 小时分别为 270 / 2,160 / 2,700 修为，且无物品或百艺 XP。
- 离线 9:59:59、10:00:00、10:00:01、72 小时。
- 批量结算结果等于逐周期结算结果。
- 当前周期换工具、升级技能、Buff 到期和配置切换。
- 大数时间、产量和 XP 不溢出、不累计浮点漂移。

### 队列

- 1 / 2 / 3 槽限制。
- 固定数量、固定时长、无限和库存条件。
- 当前项完成、目标已满足、材料不足、行动禁用、保底切换。
- 队列版本冲突不覆盖服务端状态。
- 暂停 / 恢复不绕过离线容量。
- 非法行动、未解锁条件、负目标、极大目标被拒绝。
- 当前周期预留输入后，淬炼和其他配方只能使用 `available_quantity`；取消会释放，完成会转为永久消耗。
- `SKIP` 形成 `DONE_INCOMPLETE`，`FALLBACK` 保留阻塞项；两者摘要和后续行为不同。

### 修正与快照

- 加法、乘法、软上限、舍入顺序固定。
- 标签只影响匹配行动。
- 当前周期保持旧快照，下周期使用新快照。
- 同一 Buff 组的覆盖 / 叠加规则。

### 战斗与掉落

- 固定种子重放结果一致。
- 战力增加不应在同配置下系统性降低成功率。
- 成功率始终处于配置上下限。
- 掉落数量非负，概率边界 0 / 1 正确。
- 重试结算不重新抽奖。

## 5. 事务与账本测试

每个资产事务必须验证：

- 业务状态和账本同事务提交 / 回滚。
- `balance_before + sum(delta) = balance_after`。
- 库存数据库约束拒绝负数。
- 同一 `transaction_id` 不重复写分录。
- 资产预留的创建、消耗、释放与超时恢复均幂等，且 `reserved_quantity` 永不超过总数量。
- Outbox 和业务事务同提交；重复投递由消费者去重。
- 管理员补偿生成新事务，不修改旧分录。

故障注入点：扣料前、扣料后写奖励前、奖励后提交前、提交后响应前。每个点模拟进程崩溃，恢复后结果必须唯一且完整。

## 6. 关键集成用例

| 编号 | 场景 | 预期 |
|---|---|---|
| INT-001 | 登录触发 8 小时三段结算 | 顺序、余额、摘要一致 |
| INT-002 | 材料仅够 20/100 次炼丹 | 完成 20 次后保底，无负库存 |
| INT-003 | 两设备同时保存队列 | 一个成功，一个版本冲突 |
| INT-004 | 淬炼与生产消耗同物品并发 | 串行化；只允许库存足够的事务成功 |
| INT-005 | 秘境入场响应丢失后同键重试 | 机会和入场物只扣一次 |
| INT-006 | 秘境选择重复提交 | 只接受第一次合法选择 |
| INT-007 | 秘境结果提交前服务端崩溃 | 同种子恢复，一次发奖 |
| INT-008 | 突破请求连续提交两次 | 一次扣料、一次解锁 |
| INT-009 | 洞府完成与行动周期同一时刻 | 当前周期旧修正，下周期新修正 |
| INT-010 | 配置发布时有旧运行 | 旧快照完成，新周期用新版本 |

## 7. 端到端主路径

### E2E-01 新玩家首小时

创建角色 → 修炼 → 采药 → 两项队列 → 聚气散 → 无限保底 → 装备粗制剑 → 青蛇战斗 → 青蛇洞教学 → 安排离线。

### E2E-02 标准回流

模拟 8 小时 → 登录摘要 → 检查来源 / 用途 → 修改队列 → 保存 → 整理战利品 → 下线。

### E2E-03 炼气生产闭环

挖矿 → 炼器 → 装备工具 → 对比每小时产出 → 炼丹 → 使用丹药 → 新周期修正生效。

### E2E-04 在线秘境闭环

查看机会 → 预览配置 → 入场 → 路线选择 → 断线 → 重连 → 结果 → 装备比较 / 查看用途 → 重排闭关。

### E2E-05 筑基毕业

追踪四门槛 → 补齐材料 → 预览 → 试炼 → 突破 → 3 槽 / 条件队列 / 二阶内容解锁 → 创建条件模板。

## 8. 配置测试

每次配置发布必须：

- Schema 与稳定 ID 校验通过。
- 所有引用存在、无禁用内容作为唯一来源。
- 境界、技能、洞府和淬炼梯度连续。
- 秘境图有入口、默认路线和终点。
- 概率、时间、数量、价格在合法范围。
- 每个突破材料在突破前可获得或购买。
- 每个关键材料都有非市场来源，突破、洞府和关键配方不依赖未来市场。
- Numerical Master Sheet 13 项平衡检查在导出前保持通过。
- 黄金角色使用新旧配置影子结算并生成差异报告。

阻断发布的异常：负成本、概率 >1、断引用、不可达突破、无穷循环、关键材料只有市场来源、关键结果超批准阈值。

## 9. 性能与稳定性测试

### 场景

- 200 并发会话同时登录结算 10 小时。
- 50 写请求 / 秒混合：队列、淬炼、秘境、读首页。
- 单角色恶意构造最大允许队列和分段。
- Worker 中途重启、数据库短暂断连、Redis 不可用。
- 配置热更和回滚期间持续请求。

### 通过线

- 常规读取 P95 <300 ms；队列 / 淬炼 P95 <500 ms。
- 正常登录结算 P95 <1 秒。
- 锁超时率 <0.1%，且安全重试后无资产差异。
- Redis 不可用时资产操作可降级或明确拒绝，不产生错误余额。
- 压测后账本与所有余额核对为零差异。

## 10. 安全测试

- 鉴权绕过、越权读取 / 修改其他角色。
- CSRF、XSS、注入、路径与对象 ID 枚举。
- 客户端时间篡改、请求重放、参数越界、负数量。
- 幂等键碰撞 / 复用、旧版本请求重放。
- 管理端最小权限、MFA、补偿审批审计。
- 日志不泄漏令牌、密码或不必要个人信息。

## 11. 可用性测试

每轮 5～8 名目标用户，观察而非教学。任务：

1. 安排未来 8 小时。
2. 解释回流摘要的一次行动切换。
3. 找到筑基当前最大缺口和来源。
4. 选择秘境配置并说明路线取舍。
5. 判断一个材料应立即制作、保留还是用于突破 / 洞府。

记录：完成率、首次有效操作时间、求助次数、误解、是否能复述核心循环。若多数用户把秘境理解为必须清完的日常，需修改机会和文案设计。

## 12. 缺陷等级

| 等级 | 定义 | 示例 | 发布要求 |
|---|---|---|---|
| S0 | 资产 / 数据灾难或安全泄漏 | 重复发奖、丢档、越权 | 0；立即停止发布 |
| S1 | 核心循环不可完成 | 无法结算、队列无法保存、秘境卡死 | 0 |
| S2 | 重要功能受损但有绕行 | 某配方错误、摘要缺分段 | 已知 0 或明确批准延期 |
| S3 | 轻微体验 / 表现问题 | 对齐、非关键文案 | 可带已知清单发布 |

## 13. 自动化覆盖门禁

- 规则库语句覆盖率目标 ≥90%，分支覆盖率 ≥85%；关键公式和不变量必须 100% 用例覆盖，不能用整体百分比掩盖。
- API P0 端点契约覆盖 100%。
- 五条 E2E 主路径全部自动化，另保留人工体验验收。
- 数据库迁移、配置导出和黄金重放每次 CI 执行。
- 覆盖率下降、黄金结果未批准变化、契约破坏直接阻断合并。

## 14. 发布前最终门禁

- S0 / S1 为 0，S2 有负责人逐项批准。
- 主路径自动化连续 3 次通过，无不稳定测试。
- 配置、经济、账本和迁移校验全部通过。
- 备份恢复演练成功。
- 监控面板、告警联系人、回滚步骤已验证。
- 新账号在无调试命令的环境完成垂直切片。
- 产品、技术、QA 分别签署范围、可靠性和测试结果。
