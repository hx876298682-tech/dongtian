# 《洞天》Feature Unlock Matrix V0.2

**目的：** 规定玩家何时看见、首次体验、正式开放并开始优化每个系统。  
**原则：** 一个系统不应在同一时刻同时引入入口、规则、资源、Build 和高级数据。

## 1. 解锁状态定义

| 状态 | 玩家体验 | UI 规则 |
|---|---|---|
| 隐藏 | 玩家无需知道系统存在 | 不显示入口，不弹红点 |
| 看见 | 建立长期期待，但不能操作 | 可显示锁定卡片、用途和明确条件 |
| 体验 | 通过一次受控任务理解关系 | 免费或低风险，不要求优化 |
| 正式开放 | 玩家可自由使用并承担机会成本 | 进入主导航或稳定二级入口 |
| 优化 | 加入 Build、条件、历史数据或自动化 | 只对已掌握基础循环的玩家开放 |

每次解锁只回答三个问题：这是什么、为什么需要、下一步怎么做。高级公式默认收起。

## 2. 玩家阶段总表

| 阶段 | 目标时间 | 境界目标 | 新认知预算 | 核心目标 |
|---|---:|---|---:|---|
| P0 | 0～10 分钟 | 凡人入门 | 3 | 修炼、时间、当前行动 |
| P1 | 10～30 分钟 | 凡人→炼气初期 | 3 | 采药、队列、第一炉丹 |
| P2 | 30～60 分钟 | 炼气初期 | 3 | 第一次战斗、装备、秘境看见 |
| P3 | Day 1 | 炼气中期 | 3 | 离线结算、两槽队列、战利品整理 |
| P4 | Day 2～3 | 炼气中期 | 3 | 挖矿、炼器、工具投资 |
| P5 | Day 4～7 | 炼气后期→大圆满 | 3 | 淬炼、秘境体验、筑基项目 |
| P6 | Day 7～10 | 筑基准备→筑基初期 | 3 | 多门槛突破、正式秘境、条件队列 |
| P7 | Day 10～30 | 筑基初期→后期 | 3 | 专业 Build、洞府升级、主动/挂机双循环 |
| Anchor | Day 90+ | 金丹及以后 | 未实现 | 仅保留数据和界面扩展点 |

时间是目标区间，不是登录天数硬门槛。真正解锁条件由境界、技能等级、目标任务和前置教学共同决定。

## 4. 导航与信息逐步开放

| 阶段 | 一级导航 | 快捷入口 | 禁止展示 |
|---|---|---|---|
| P0 | 洞府、修炼 | 背包、当前行动 | 坊市、淬炼、宗门 |
| P1 | +百艺 | 闭关计划 | 高阶配方、利润公式 |
| P2 | +历练、角色 | 秘境机会 | 筑基后秘境与复杂策略 |
| P3 | 同上 | 目标追踪、战利品用途 | 坊市、价格、交易、自动交易 |

宗门和坊市作为未来世界观存在时，只能出现在不可交互的叙事文本或远景中，不占一级导航。

## 6. 解锁判断伪规则

```text
visible = realm >= visible_realm
          AND prerequisite_tutorials complete

usable = visible
         AND realm >= usable_realm
         AND skill_level >= required_skill_level
         AND feature_flag enabled

optimized_ui = usable
               AND mastery_condition complete
```

服务端返回最终权限；客户端只负责表现，不可通过本地改值解锁内容。

## 7. 一致性约束

- 炼气期只有顺序队列；条件队列在筑基解锁。
- 队列槽位：凡人 1、炼气 2、筑基 3。
- 药力槽：炼气早期 1、炼气后期 2、筑基 3。
- 筑基进入条件来自实际资产、材料、修为和试炼，不以登录天数直接解锁。
- 主动秘境不会暂停闭关行动；两者分别结算。
- 金丹、元婴、化神只保留数据锚点，不在 MVP UI 中暴露可操作入口。
