# 《洞天》MVP PRD 与验收标准 V1.0

## 1. 产品目标

证明以下三件事，而不是在 MVP 内证明所有 MMO 能力：

1. 玩家愿意主动规划未来 8～12 小时，而非只点领取。
2. 挂机生产与在线秘境形成互相支持的双循环。
3. 境界能自然承担内容和复杂度门槛，第一次筑基像一次阶段毕业。

## 2. 目标用户与使用场景

目标用户喜欢修仙、放置成长、资源经营或轻度 Build，能够接受数字与表格信息，但不希望被固定时间活动绑架。

标准日循环：

```text
早上：收取约 8～10 小时收益 → 修正队列 → 可选快速处理
晚上：收取收益 → 配装/用丹 → 进行 1～3 次秘境 → 处理战利品 → 安排夜间闭关
```

单次在线目标约 25 分钟；玩家只收取和重排也能在 3～5 分钟内安全离开。

## 3. 核心用户故事

### US-01 收取离线结果

作为回流玩家，我希望一次看懂离线期间做了什么、获得什么、哪里中断，以便判断下一步。

验收：

- 登录后服务端自动结算，无需点击才继续计时。
- 摘要按行动分段显示耗时、产物、XP、消耗与中断原因。
- 10 小时内离线模拟结果与等长在线模拟一致，允许的数值误差小于 `1e-6`。
- 超过上限的时间明确显示为未结算，不伪装成资源损失。

### US-02 安排闭关计划

作为玩家，我希望安排多个行动和一个保底行动，离开后仍按计划执行。

验收：

- 凡人 1 槽、炼气 2 槽、筑基 3 槽由服务端校验。
- 支持固定数量、固定时长、无限执行；筑基支持简单库存条件。
- 保存前提供预计时长、材料缺口与预计产出。
- 保存是版本化原子操作，冲突时提示刷新，不覆盖另一设备的新计划。

### US-03 在线秘境

作为上线玩家，我希望通过装备、丹药和路线选择提升秘境收益，而不是只观看自动战斗。

验收：

- 进入前显示推荐战力、预计成功率区间、入场成本与核心掉落。
- 进入后战斗自动执行，至少包含一次路线/风险选择。
- 闭关行动在秘境期间继续推进。
- 秘境机会在确认进入后扣除；重复请求、断线重连不会重复扣除或发奖。
- 结果页能直接比较装备、查看材料用途，并返回闭关规划。

### US-04 生产与装备成长

作为生产玩家，我希望采集、炼丹、炼器和工具投资能提高单位时间价值。

验收：

- 每个行动显示基础耗时、当前修正、每小时预估与经验。
- 配方显示材料、库存、耗时、产物、技能要求和来源跳转。
- 工具只影响之后开始的行动；不追溯修改已结算历史。
- 炼丹、炼器批量任务按可完成整次行动结算，尾部不足一次的时间留待下次。

### US-05 战利品处理

作为玩家，我希望秘境结束后能快速判断装备和材料应如何使用，而不是被交易系统打断游玩闭环。

验收：

- 装备支持比较、装备、保留和查看淬炼用途。
- 材料支持查看生产、洞府、淬炼和突破用途及非市场来源。
- 所有 MVP 必需资源都能通过修炼、采集、生产、普通战斗、秘境、教程或目标奖励获得。
- MVP 不显示坊市导航，不实现报价、买卖、NPC 回收、玩家订单或跨玩家转移。

### US-06 筑基项目

作为炼气大圆满玩家，我希望明确知道筑基缺什么、如何获得、预计多久完成。

验收：

- 目标追踪同时展示累计修为 24,100、筑基丹 1、灵髓 3、护脉丹 2、灵石 2,500 与资产覆盖。
- 点击任一缺口可进入采集、配方、普通战斗或秘境来源。
- 所有条件满足后可进入 15 分钟筑基试炼。
- 突破成功率 100%；重复提交不会重复消耗或重复发放解锁。
- 成功后解锁 3 槽闭关、条件队列、3 药力槽、二阶百艺和正式筑基秘境。

## 4. MVP 功能范围

### P0：必须交付

- 账号 / 匿名测试身份、角色创建、服务端时间。
- 洞府首页、修炼、百艺、历练、角色、背包。
- 当前行动、顺序队列、无限保底、筑基简单条件队列。
- 在线与离线确定性结算、结算摘要、行动日志。
- 修为和境界；凡人、炼气四阶段、筑基四阶段数据结构。
- 采药、挖矿、炼丹、炼器、工具和基础淬炼。
- 剑修装备、自动普通战斗、2 个 MVP 秘境。
- 战利品整理、装备比较、材料来源 / 用途和经济账本。
- 聚灵室、炼丹房、炼器房。
- 筑基多门槛项目与试炼。
- 新手引导、目标追踪、设置、基础无障碍与错误恢复。
- 配置发布、日志、监控、埋点、备份和管理员只读查询。

### P1：Alpha 前补充

- 内容扩充至 GDD 建议上限。
- 基础收藏、更多战斗策略预设、平衡实验工具。
- 管理员补偿与配置灰度 UI。
- 市场扩展 ADR 与数据迁移评审；不进入 Alpha 前功能开发。

### 明确不做

- PVP、实时组队、固定时刻活动、每日任务红点体系。
- 模拟市场、NPC 商店、玩家市场、报价、买入、卖出和交易撮合。
- 宗门功能、御兽、阵法、灵膳、道侣、坐骑、开放世界移动。
- 法修、体修完整流派和复杂五行克制。
- 金丹以上可玩内容、法宝、分身、高阶自动采购/出售。
- 抽卡角色、售卖数值资源、离线收益付费翻倍。
- 玩家自由聊天与用户生成内容。

## 5. 内容下限

MVP 可玩版本的最低内容量：

| 类别 | 下限 | 说明 |
|---|---:|---|
| 采集行动 | 8 | 采药 4、挖矿 4 |
| 丹药 | 8 | 含聚气、恢复、百艺、战斗、筑基 |
| 炼器配方 | 15 | 工具、丹炉、武器、防具 |
| 工具 | 10 | 药锄、矿镐、丹炉梯度 |
| 可装备物 | 10 | 武器、防具、饰品 |
| 普通区域 | 6 | 同时承载采集、战斗或目标 |
| 普通妖兽 | 8 | 可含同模型换生态变体，但数值和掉落不同 |
| Boss | 2 | 至少一个承担筑基材料目标 |
| 秘境 | 2 | 青蛇洞 + 玄铁秘窟；黑风秘境为筑基 Endgame 内容 |
| 洞府设施 | 3 | 每项至少 3 个可升级等级 |

数值母表现有条目作为首批实现种子；缺口由内容制作清单补足。

## 6. 非功能需求

### 一致性与安全

- 服务器为资产、时间、掉落、突破和解锁的唯一权威。
- 所有资产变化写入双边可审计账本；余额不可直接无来源覆盖。
- 关键写操作必须带幂等键，支持至少 24 小时重复请求去重。
- 客户端本地时间不参与结算。

### 性能目标

- 常规读取 API 服务端 P95 小于 300 ms，不含公网和首次冷启动。
- 队列保存 / 淬炼 P95 小于 500 ms。
- 登录离线结算在 1,000 个行动分段以内 P95 小于 1 秒；正常设计应远低于该分段数。
- 页面首次可交互目标小于 3 秒，核心操作反馈小于 150 ms；服务端未确认时使用明确等待态。

### 可靠性

- 任何进程中断不得造成重复发奖、重复扣费或负库存。
- 数据库每日备份，关键账本具备时间点恢复能力。
- 配置发布可在 10 分钟内回滚到上一版本。
- 测试与 Alpha 环境严格隔离。

### 可访问性与设备

- 桌面宽度 1280～2560 可用；最小目标宽度 1024。
- 关键含义不只依赖颜色；键盘可完成核心流程。
- 数字支持千分位、缩写切换和完整值 Tooltip。

## 7. 产品级成功指标

内部可玩性测试：

- 80% 测试者在 10 分钟内说清“当前行动—队列—离线”的关系。
- 70% 测试者在第二次回流时主动修改队列，而非原样继续。
- 70% 测试者能在不查外部攻略时指出筑基的最大缺口和至少一种来源。
- Day 7 模拟或加速测试中，均衡玩家达到炼气大圆满附近；Day 10 具备筑基条件。
- 筑基阶段主动秘境价值占总成长价值 25%～35%。
- 测试经济 Sink / Faucet 比例 75%～100%，并且没有负库存或重复资产。

## 8. 发布验收场景

### 场景 A：完整回流循环

1. 玩家安排采药 2 小时、炼丹 100 次、无限修炼。
2. 模拟离线 10 小时。
3. 登录后结算按顺序完成，可追溯材料与余留时间。
4. 玩家修改队列，保存成功。

通过条件：结果与确定性模拟器一致，重复登录不再次发放。

### 场景 B：材料不足

1. 队列计划炼丹，但库存只够 20 次。
2. 系统完成 20 次后触发材料不足。
3. 根据玩家设置跳过至下一项或进入保底行动。

通过条件：不产生负库存，摘要说明缺少哪种材料。

### 场景 C：秘境断线

1. 玩家使用幂等键进入秘境并扣除一次机会。
2. 战斗中断线并重连。
3. 服务端恢复同一次运行或返回已经结算的结果。

通过条件：机会、入场物和奖励各变化一次。

### 场景 D：筑基重复提交

1. 条件齐全，客户端连续提交两次突破。
2. 服务端只创建一个突破事务。

通过条件：材料只扣一次，境界只提升一次，解锁只写一次。

## 9. MVP 完成定义

只有在垂直切片可由新账号连续完成、所有 P0 验收通过、严重级缺陷为 0、经济与结算账本可审计、配置可回滚、核心埋点可查询时，MVP 才算完成。内容数量或画面精度不足可以阻止公开 Alpha，但不能用演示脚本替代真实系统链路。
