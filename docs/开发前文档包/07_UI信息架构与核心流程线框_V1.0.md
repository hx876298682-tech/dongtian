# 《洞天》UI 信息架构与核心流程线框 V1.0

## 1. 体验目标

界面首先是一套清楚、可信、可规划的现代工具，其次才是修仙氛围。玩家每次进入都应在 5 秒内回答：

1. 我现在是什么阶段？
2. 离开期间发生了什么？
3. 当前在做什么，多久结束？
4. 下一目标缺什么？
5. 我现在最值得做的一个决定是什么？

视觉比例：现代产品 UI 70%，东方修仙氛围 30%。避免满屏金边、巨大书法字、页游按钮和红点海洋。

## 2. 桌面信息架构

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 道号 / 境界 / 修为                    灵石  秘境机会  背包  设置            │
├───────────┬──────────────────────────────────────────────┬─────────────────┤
│ 洞府      │                                              │ 当前闭关        │
│ 修炼      │                中央工作区                    │ 01 采药 43%     │
│ 历练      │                                              │ 02 炼丹 ×100    │
│ 百艺      │                                              │ 保底 无限修炼   │
│ 角色      │                                              │ [编辑计划]      │
│           │                                              │                 │
├───────────┴──────────────────────────────────────────────┴─────────────────┤
│ 状态 / 错误 / 保存反馈                                                       │
└────────────────────────────────────────────────────────────────────────────┘
```

- 顶栏高度固定，显示最关键长期状态。
- 左侧一级导航 5 个；洞府设施作为洞府二级页，不另设一级入口。坊市不在 MVP 渲染。
- 右侧闭关栏常驻，可折叠但默认展开。
- 详情通过右抽屉或模态显示，不把玩家频繁踢离当前上下文。
- 宗门不在 MVP 导航出现。

## 4. 洞府首页

```text
┌─ 炼气后期 ───────────────────────────┐  ┌─ 下一个目标：筑基 ─────────────┐
│ 修为 12,840 / 24,100   预计 3天8小时 │  │ 修为       53%                │
│ 当前：玄铁岭挖矿       00:42:18      │  │ 筑基丹      0 / 1   [查看来源] │
└──────────────────────────────────────┘  │ 灵髓        2 / 3   [查看来源] │
┌─ 最近闭关 ───────────────────────────┐  │ 护脉丹      2 / 2              │
│ 8小时31分 · 4段行动 · 1次稀有掉落    │  └───────────────────────────────┘
│ +青灵草 86  +玄铁矿 12  +修为 1,402  │  ┌─ 洞府 ───────────────────────┐
│ [查看完整摘要]                        │  │ 聚灵室 Lv2  炼丹房 Lv1        │
└──────────────────────────────────────┘  │ [管理设施]                    │
```

规则：

- 收益摘要只突出 3～5 个最重要结果，完整明细另开抽屉。
- “预计完成”使用当前计划的估算，并标注会受材料和玩家修改影响。
- 首页不显示综合战力大数字。

## 5. 离线收益摘要

首次回流使用可关闭的居中面板：

```text
你闭关了 8小时31分
有效结算 8小时31分 · 离线上限 10小时

时间轴
采药 2:00 ─ 炼丹 1:18 ─ 修炼 5:13

获得                 消耗
青灵草 +86           青灵草 -60
聚气丹 +20           凝露花 -20
修为 +1,402
采药 XP +311

稀有：凝露花 ×2
[查看分段]                     [继续修行]
```

异常行：

- 材料不足：“炼丹完成 20/100 次后缺少凝露花，已转为无限修炼。”
- 超上限：“另有 2小时15分超过当前 10 小时离线上限，未参与结算。”
- 配置更新：“1 个旧行动已安全完成，后续使用新版本。”

弹层关闭后结算已继续；不存在“不领取就停止”的规则。

## 6. 闭关计划编辑器

```text
闭关计划                              预计覆盖 9小时18分
┌───────────────────────────────────────────────────────┐
│ 1  百草谷采药     固定 2小时     预计 +87 青灵草   ⋮ │
│ 2  炼制聚气丹     100次          缺 凝露花 42      ⋮ │
│ 3  [筑基] 修炼    直到修为…      条件有效          ⋮ │
├───────────────────────────────────────────────────────┤
│ 保底：无限修炼                                      ⋮ │
└───────────────────────────────────────────────────────┘
[+ 添加行动]                       [预览] [保存计划]
```

交互：

- 拖拽和键盘按钮均可排序。
- 每项显示方式、目标、预计时间、主要产出和阻塞警告。
- 保存前必须先调用预览，但预览失败不丢本地编辑。
- 两设备版本冲突时展示“服务器计划 / 我的计划”，不静默覆盖。
- 筑基条件编辑器使用结构化控件，不允许自由文本脚本。

状态：

- 空：提供三套模板，不出现纯空白。
- 加载：保留骨架与上次本地只读快照，不允许误编辑。
- 锁定：解释需要筑基及其价值。
- 失败：保留编辑内容，提供同幂等键重试。

## 7. 百艺列表与详情

列表卡片显示：技能等级、当前 XP、当前工具、最佳已解锁行动、每小时价值和是否正在执行。

详情页：

```text
采药 Lv20                        12,430 / 15,100 XP
玄铁药锄：速度 +22% · 效率 +10%   [更换]

地点         耗时     产出/小时      XP/小时     状态
百草谷       92.6秒   青灵草 43.5    155.5       可用
雾隐坡       129.6秒  凝露花 31.1    194.4       可用
灵泉谷       175.9秒  紫叶兰 22.9    225.1       推荐
筑基药园     —        —              —           筑基解锁
```

点击行动打开详情抽屉：来源、用途、稀有产物、修正拆解、加入队列。

利润和价值指数不是新人默认主列；筑基后可在“高级数据”展开。

## 8. 炼丹 / 炼器

- 左侧筛选配方，中央显示配方与批量预估，右侧保持闭关队列。
- 材料数量可点击跳到来源，不自动替玩家购买。
- 批量输入支持数量和“使用现有材料最大制作”；后者必须显示实际可完成数。
- 配方加入队列，不提供脱离时间系统的即时无限制作。
- 亏损配方不用红色恐吓；显示“当前模拟卖价低于材料成本”，让玩家基于自用价值决定。

## 9. 角色与装备

```text
             [武器]
 [饰品]      修士轮廓      [防具]

当前配置：玄铁剑 / 玄铁甲 / 青玉佩
攻击 45   防御 36   生命 230   速度 +4%

秘境预估
玄铁秘窟：胜率约 65%～80%   主要短板：防御

[预设1 均衡] [预设2 秘境] [+ 新预设]
```

- 装备比较显示主要属性差、适用标签和来源。
- “战力”仅用于秘境推荐比较，不作为首页唯一目标。
- 换装明确提示“对下个闭关周期生效；已进入秘境不变”。

## 10. 秘境完整流程

### 10.1 入口

区域页显示机会 `3/6`、下次恢复、已解锁秘境和核心掉落。

### 10.2 准备页

```text
玄铁秘窟                      推荐战力 450
你的预估：约 65%～80%

装备预设  [秘境配置 ▼]
丹药      回春丹 ×2 / 炼体丹 ×1
策略      生命 <40% 使用回春丹
入场      秘境残片 ×1

路线预览：左侧矿脉 / 右侧妖巢（进入后选择）
核心掉落：黑风晶、玄铁剑

[返回]                              [消耗1次机会进入]
```

按钮旁明确写出机会和入场物；提交期间禁用重复点击，但仍依赖服务端幂等。

### 10.3 运行页

- 顶部展示进度节点和可安全离开说明。
- 战斗日志可折叠，默认只显示关键事件。
- 路线选择卡必须展示风险、预期奖励类型和自动选择倒计时。
- 断线重连后回到同一 `run_id`。

### 10.4 结果页

```text
秘境完成 · 9分42秒
路线：废弃矿脉 → 守卫厅

获得：黑风晶 ×1、玄铁剑 ×1、修为 +400
消耗：秘境残片 ×1、回春丹 ×2

玄铁剑（新） vs 青铜剑（当前）   [装备] [保留]
黑风晶                            [查看用途] [加入目标]

[再次挑战] [返回历练] [调整闭关计划]
```

奖励在结果生成时已入账；按钮不是领取按钮。

## 11. 坊市扩展位置

MVP 不显示坊市导航、锁定卡、价格、买卖或 NPC 回收，也不创建一个可点击空页面。

只在导航配置和页面枚举中保留 `feature.market` / `route.market` 稳定 ID，默认 `enabled=false`。未来市场立项时在左侧导航预留位置插入，不需要重构现有五个一级导航。所有首版材料来源和用途页面不得链接未实现的坊市。

## 12. 筑基目标与突破

目标页按四类门槛组织：修为、关键配方、秘境材料、资产 / 试炼。每项给出当前值、要求、预计完成和 2～3 个真实来源。

突破确认页必须显示：

- 将消耗的物品和灵石。
- 15 分钟试炼配置。
- “准备充分后成功率 100%”。
- 解锁：3 槽闭关、条件队列、3 药力槽、二阶百艺、正式筑基秘境。

成功表现重点是世界和玩法扩大，不是只弹属性 `+30%`。

## 13. 洞府

设施卡显示等级、当前累计效果、下一等级成本、建造时间和预估回本。一次只显示对当前决策有用的解释。

建造中显示服务端完成时间；关闭游戏不会停止。完成后的加成在下个完整行动周期生效。

## 14. 通用状态与反馈

每个数据页面必须有：

- 首次空状态：解释价值 + 一个主要动作。
- 加载状态：稳定骨架，避免布局跳动。
- 局部失败：只重试失败区域，保留其他可用内容。
- 锁定状态：条件、价值和可追踪目标。
- 维护 / 版本过旧：明确不会丢失离线进度。

写操作反馈分三层：按钮即时状态、页面内确认、活动日志可追溯。禁止只用短暂 Toast 表示关键资产变化。

## 15. 数字与文案

- 小于 10,000 默认显示完整值；大数可缩写但悬停显示完整值。
- 概率面向玩家显示合理区间；实际消耗和余额显示精确值。
- “离线收益”统一称“闭关所得”或“离线结算”，避免“领取双倍”。
- “失败”必须解释原因和下一步，不使用羞辱或催促性文案。
- 目标提示说“建议”，不制造每日清空焦虑。

## 16. 视觉与组件基线

- 颜色：墨青、米白、青玉、低饱和金；危险和错误使用克制红色。
- 字体：正文使用清晰现代无衬线；展示标题可少量使用有东方气质的字体，但不能影响数字阅读。
- 图标：资源图标轮廓清晰，16 / 24 / 32 / 64 四档适配；稀有度不能只靠颜色。
- 组件：状态卡、资源 Chip、进度条、队列项、来源链接、对比表、风险选择卡统一复用。

## 17. 响应式与无障碍

- ≥1440：三栏常驻。
- 1024～1439：左导航缩窄，右队列可覆盖抽屉。
- <1024：不是 MVP 正式适配目标，但页面不可完全不可用；后续移动版单独设计。
- 所有核心按钮有可见焦点；拖拽有键盘替代。
- 文本和背景满足可读对比；状态同时用图标 / 文案表达。
- 动效可减少；秘境自动战斗提供跳过表现但不跳过服务端规则。

## 18. UI 验收分辨率

至少在 1024×768、1280×720、1440×900、1920×1080、2560×1440 验证：无关键文本截断、无按钮被队列栏遮挡、表格可横向处理、模态不超出视口、缩放 125% 可用。

## 19. 单视口布局与滚动门禁（MUST）

### 19.1 目标视口

以下尺寸是首版必须通过验收的目标视口，按 CSS viewport 检查，不以设备物理分辨率替代：

| 端 | 目标视口 | 必须保持的结构 |
| --- | --- | --- |
| 桌面 | 1440×900 | 固定顶栏 + 左导航 + 主内容区 + 右闭关栏 + 固定底栏 |
| 桌面 | 1366×768 | 固定顶栏 + 左导航 + 主内容区 + 右闭关栏 + 固定底栏 |
| 移动 | 390×844 | 固定顶栏 + 主内容区 + 固定底部导航 |
| 移动 | 375×667 | 固定顶栏 + 主内容区 + 固定底部导航 |

### 19.2 布局 MUST

- `body`、页面根容器和路由级页面 MUST 锁定为单视口布局；内容不得通过页面整体向下延伸来承载信息。
- 桌面端 MUST 始终保留固定顶栏、左侧一级导航、主内容区、右侧闭关栏和底部状态栏；各栏不能随主内容滚出视口。
- 桌面端顶栏、底栏、左导航和右闭关栏 MUST 使用稳定尺寸或稳定最小尺寸；主内容区只能占用剩余空间。
- 移动端 MUST 始终保留固定顶栏和固定底部导航；左导航、右闭关栏改为抽屉或局部面板，不得挤压主内容造成页面级溢出。
- 仅允许主内容面板内部滚动，或列表、表格、日志、抽屉等明确标注的局部容器内部滚动；局部滚动容器 MUST 有独立滚动边界和可见焦点顺序。
- 顶栏、底栏、导航和右闭关栏遮挡区域内的内容 MUST 通过内边距或安全区预留完整可见空间；最后一项不能被固定栏覆盖。
- 模态、抽屉和确认面板 MUST 在当前视口内完整呈现；内容超出时只能在面板内部滚动，不能把滚动责任转移给 `body`。
- 在四个目标视口和浏览器缩放 125% 下，核心操作、当前状态、错误反馈和返回路径 MUST 可见且可操作。

### 19.3 禁止项

- 禁止 `body`、`html`、页面根节点出现纵向滚动条，禁止用页面级滚动解决信息过载。
- 禁止通过增加页面高度、底部留白、隐藏溢出内容或缩小到不可读字号来“适配”目标视口。
- 禁止固定栏随页面滚动、主内容滚动时发生布局跳动，或局部列表滚动穿透到页面根容器。
- 禁止移动端将桌面五栏直接压缩到同一行，或通过横向页面滚动代替抽屉、折叠和局部列表处理。
- 禁止关键按钮、资源余额、行动进度、错误信息和保存反馈落在视口外；禁止依赖用户滚到页面底部才能完成核心流程。
- 禁止新增任何未定义滚动边界的无限高度组件；长日志、表格和计划列表必须限制在所属面板内。

### 19.4 验收标准

在 1440×900、1366×768、390×844、375×667 四个目标视口分别打开洞府、修炼、百艺详情、闭关计划编辑器、秘境准备 / 运行 / 结果、角色和离线结算面板，必须全部满足：

1. 浏览器窗口不出现页面级纵向滚动条；`html`、`body` 和路由根容器的实际高度不超过视口可用高度。
2. 桌面五个固定区域和移动两个固定区域始终可见，且不遮挡主内容的标题、操作按钮、底部列表项或错误反馈。
3. 需要承载超出内容的地方仅出现主内容面板或明确局部容器的滚动条；滚动局部容器时页面位置不移动。
4. 键盘 Tab、触摸滑动和鼠标滚轮都能进入并退出局部滚动区域；焦点不会落入不可见或被固定栏遮挡的控件。
5. 加载、空状态、失败、锁定、长文案、长列表、打开抽屉和打开模态等状态均不改变页面级滚动约束。
6. 任一页面出现 `body` / 页面根容器纵向滚动、核心信息只能滚到视口外才能访问、或固定栏遮挡内容，即判定为验收失败。

### 19.5 发布阻断规则

页面级滚动是阻断发布的问题，不是体验优化项。任一目标视口出现页面级纵向滚动条，或通过页面滚动才能看到核心状态 / 完成核心操作，均 MUST 标记为 **Release Blocker**，不得进入演示验收、Alpha 发布或生产发布。只有将溢出收敛到主内容面板或明确局部列表容器，并重新通过四个目标视口验收后，才可解除阻断。
