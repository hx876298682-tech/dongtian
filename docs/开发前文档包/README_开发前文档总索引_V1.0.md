# 《洞天》开发前文档总索引 V1.0

**项目：** 修仙 Idle MMO（暂定名《洞天》）  
**阶段：** MVP 立项与开发准备  
**范围：** 凡人、炼气、筑基；金丹及以后仅保留扩展锚点  
**基线日期：** 2026-08-15  
**文档负责人：** 产品 / 系统策划；进入开发后由对应负责人共同维护

## 1. 本文档包解决什么问题

本包把 GDD 与数值母表转化为可开发、可验收、可测试的执行基线。开发团队不应再从叙述性设计中自行猜测规则。

MVP 只验证一条核心体验：

> 玩家收取离线结果，理解发生了什么，重新安排未来 8～12 小时；上线期间可通过秘境配置与路线选择获得高价值材料和装备，之后处理战利品并再次规划。

完整垂直切片必须贯通：

```text
登录
→ 服务端结算离线进度
→ 展示收益与异常原因
→ 编辑闭关计划
→ 保存并开始执行
→ 配置并完成一次在线秘境
→ 处理装备 / 材料 / 制作用途
→ 再次安排闭关
→ 下线后继续可靠结算
```

## 3. 规则权威顺序

出现冲突时按以下顺序处理：

1. 已批准且日期最新的决策记录。
2. MVP PRD 的范围与验收标准。
3. 子系统规则规格、API 契约与数据规范。
4. Numerical Master Sheet 中的数值及公式。
5. GDD 中的设计意图。
6. 竞品逆向资料。

任何人发现冲突，必须新增决策记录并同步修改受影响文档；不得只在代码中形成隐性规则。

## 4. MVP 已锁定基线

| 维度 | 开发基线 |
|---|---|
| 平台 | PC / Web 优先，响应式覆盖常见桌面宽度 |
| 境界 | 凡人、炼气、筑基；筑基为 MVP Endgame |
| 核心百艺 | 采药、挖矿、炼丹、炼器、淬炼 |
| 战斗 | 剑修；自动战斗，玩家负责入场配置与路线决策 |
| 世界内容 | 6 个普通区域、2 个正式 MVP 秘境、8～12 种妖兽、2～3 个 Boss |
| 市场 | MVP 不开发；只保留 `feature.market`、模块命名和未来扩展边界 |
| 洞府 | 聚灵室、炼丹房、炼器房，各 3～4 个 MVP 等级 |
| 离线容量 | 基础 10 小时 |
| 在线节奏 | 目标每日 2 次、每次约 25 分钟；不是强制日常 |
| 秘境机会 | 每 12 小时恢复 1 次，上限 6 次，不按日清空 |
| 挂机与主动价值 | 筑基阶段目标约 70% / 30% |
| 筑基目标 | 均衡玩家 Day 7 接近准备完成，Day 10 左右突破 |
| 突破失败 | 准备充分后 100% 成功；不损失长期投入 |

## 5. 版本与变更规则

- 文档版本采用 `主版本.次版本`。破坏实现或数据兼容性的变更提升主版本。
- 配置发布采用不可变 `config_version`，所有结算记录携带版本号。
- 任何影响玩家资产、产出、掉落、消耗或突破条件的改动，必须同时提交：配置差异、迁移策略、回归用例、数据监控项。
- 任何新增系统必须回答 GDD 附录 B 的十个检查问题，并进入解锁矩阵。
- 开发期间不直接修改历史结算；修复采用补偿账本。

## 6. Definition of Ready：功能进入开发前

一项功能只有同时满足以下条件才能进入开发：

- 用户问题、核心流程与非目标明确。
- 解锁阶段、入口和教程触发已定义。
- 正常、空、加载、失败、锁定五类 UI 状态已定义。
- 数据实体、配置字段、接口与错误码已定义。
- 经济 Faucet / Sink 及 Numerical Master Sheet 影响已说明。
- 边界规则、幂等键、并发与重连行为已定义。
- 验收标准与测试用例可执行。
- 埋点事件与核心属性已定义。
- 美术、文案、音效依赖有占位或正式资产计划。

## 7. Definition of Done：功能交付完成

- 产品验收标准全部通过。
- 单元、集成、端到端与配置校验通过。
- 客户端不承担权威结算，断线重试不会重复发奖或扣除。
- 关键状态可追踪，关键经济变化进入不可变账本。
- 埋点可在测试环境查询并通过事件校验。
- 关键页面在目标分辨率无截断、无阻断性空白状态。
- 配置可回滚，数据库迁移有回退或前向修复方案。
- 已更新受影响文档和版本说明。

## 8. 开工门禁

在建立正式项目仓库和第一个 Sprint 前，负责人逐项确认：

- [x] 核心 GDD 已有明确 MVP 范围。
- [x] 数值母表覆盖成长、资源、装备、突破与经济模拟。
- [x] 解锁矩阵与玩家时间轴已定义。
- [x] MVP PRD 与明确非目标已定义。
- [x] 离线结算、队列、秘境并发和补偿规则已定义。
- [x] 数据模型、配置、ID 与版本规则已定义。
- [x] 技术架构、服务端权威和事务边界已定义。
- [x] API 契约与错误码已定义。
- [x] 核心 UI 流程与页面状态已定义。
- [x] 测试、埋点与经济监控已定义。
- [x] 垂直切片、里程碑和开发拆解已定义。
- [x] MVP 内容与资产清单已定义。

满足上述门禁后可以开始垂直切片开发；Alpha 内容扩量仍以真实测试数据为依据。
