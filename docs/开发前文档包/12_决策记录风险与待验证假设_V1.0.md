# 《洞天》决策记录、风险与待验证假设 V1.0

## 1. 使用方式

本文件记录已经足以支持开工的默认决策，以及必须通过原型 / Alpha 验证的产品假设。待验证不等于开发阻塞；除非出现新证据，团队按“当前决策”执行。

状态：`已确定`、`试行`、`已替代`、`待决定`。只有 `待决定` 且标记“阻塞”才阻止相关开发。

## 3. 产品假设与验证

| H | 假设 | 验证方法 | 成功线 | 失败后的优先动作 |
|---|---|---|---|---|
| H-001 | 玩家会主动规划 8～12 小时 | 回流可用性测试、queue_saved | 第二次回流 ≥70% 主动改计划 | 改进预览、目标缺口和模板 |
| H-002 | 闭关队列本身有策略乐趣 | 对比多种合法计划与访谈 | 玩家能解释至少一个取舍 | 增加清楚的资源依赖，不加点击劳动 |
| H-003 | 秘境能贡献约 30% 价值 | 账本价值拆分 | 筑基主要落在 25%～35% | 调机会、奖励或耗时，不做每日清空 |
| H-004 | 非战斗专业能长期成立 | 三画像模拟 + Alpha 行为 | 丹师 / 采集者有独立目标和资产增长 | 增强消费需求和专业效率 |
| H-005 | 筑基像毕业而非数字门 | Day7/10、访谈、漏斗 | 70% 能说出最大缺口，完成有机制感 | 减少门槛项或改善来源引导 |
| H-006 | 市场能否产生有趣选择 | 延后到市场专项立项 | 不影响 MVP 验收 | 完成游玩闭环后另写市场 PRD 与技术方案 |
| H-007 | 10 小时离线上限适配生活 | capped_seconds 分布 | 超上限玩家 <20% | 提高容量或提供非付费成长解锁 |
| H-008 | 三栏 UI 不像后台 | 可用性与审美访谈 | 80% 能快速定位当前行动和目标 | 强化首页叙事和视觉层级 |

## 5. 未来决策触发点

| 触发 | 需要的新决策 |
|---|---|
| 核心游玩闭环、筑基 Endgame 和资产审计稳定 | 是否另行立项市场原型 |
| 筑基核心循环数据稳定 | 金丹内容与高阶遗迹范围 |
| PC / Web 留存成立 | 是否做移动端原生或响应式重构 |
| 内容生产速度可预测 | 法修 / 体修中的下一流派 |
| 经济 4 周稳定 | 商业化方案与不可出售清单复审 |
| 宗门进入排期 | 异步贡献、个人进度和反搭便车规则 |

## 7. 开工结论

产品范围、核心规则、数据模型、架构、接口、UI、测试、分析、内容与里程碑已有一致基线。团队可以从 M0 和垂直切片开始；真正需要通过开发验证的是“是否好玩”，不再是“规则到底是什么”。
