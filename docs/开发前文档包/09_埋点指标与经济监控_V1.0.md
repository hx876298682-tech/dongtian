# 《洞天》埋点、指标与经济监控 V1.0

## 1. 分析目标

数据首先回答三个产品问题：

1. 玩家是否在做有意义的闭关规划？
2. 在线秘境是否有价值但没有变成强制清单？
3. 筑基是否是清楚、可达、有满足感的阶段毕业？

其次监控资产一致性、Faucet / Sink、配方、材料可达性和库存积压。

## 2. 数据原则

- 权威资产、结算、淬炼和秘境事件由服务端产生。
- UI 浏览、点击和曝光由客户端产生，但服务端关联最终结果。
- 事件至少包含 `event_id`、UTC 时间、匿名用户 / 角色 ID、会话 ID、客户端版本、配置版本、实验桶。
- 不采集聊天内容、密码、令牌或不必要个人信息。
- 同一业务事务使用 `transaction_id` 关联事件和账本。
- 事件通过事务 Outbox 至少一次投递，分析端按 `event_id` 去重。

## 3. 核心事件字典

### 会话与回流

| 事件 | 触发 | 关键属性 |

| `offline_summary_viewed` | 摘要曝光 | settlement_id, expanded_segments |
| `session_ended` | 正常离开或超时 | duration_seconds, last_page |

## 4. 北极星与辅助指标

### 北极星：有意义规划回流率

定义：在一次 `offline_settlement_completed` 后 15 分钟内成功保存一个与旧队列有实质变化、且预计覆盖至少 4 小时的计划的回流会话比例。

```text
Meaningful Planning Return Rate
= 满足条件的回流会话数 / 有有效离线结算的回流会话数
```

“实质变化”包括行动类别、顺序、时长 / 数量、条件或保底变化；只重新保存相同队列不计。

### 辅助指标

- 队列覆盖时长中位数与 P25 / P75。
- 因材料不足进入保底的比例。
- 离线容量利用率与超上限比例。
- 秘境机会使用率、封顶时长、每周进入次数分布。
- 主动秘境价值占总成长价值。
- 筑基门槛分项耗时和 Day 7 / Day 10 准备度。
- 采集、生产、普通战斗与秘境的关键物品来源占比。
- 洞府 / 工具 / 淬炼的实际回本时长。

## 5. 漏斗

### 新手核心认知漏斗

```text
创建角色
→ 首次修炼
→ 首次采药
→ 首次保存两项队列
→ 首炉丹药
→ 设置保底行动
→ 首次有效回流摘要
→ 回流后修改队列
```

### 秘境漏斗

```text
秘境入口曝光
→ 准备页
→ 预览配置
→ 入场
→ 做出路线选择
→ 完成 / 失败
→ 处理战利品
→ 调整闭关或再次挑战
```

### 筑基漏斗

```text
筑基目标首次曝光
→ 查看缺口
→ 点击来源
→ 四门槛逐项达成
→ 开始试炼
→ 完成突破
→ 首次保存条件队列
```

## 6. 留存与节奏

仍记录 D1、D3、D7、D14、D30 留存，但不通过每日任务人为制造登录。额外使用更适合本产品的节奏指标：

- 72 小时内第二次有效回流。
- 一周内至少 3 次有效规划会话。
- 离线容量封顶前回流比例。
- 机会达到 6/6 后 24 小时仍未使用的玩家比例。
- “只领不改”连续 3 次会话比例。

如果留存只由强提醒或机会封顶驱动，不算核心循环成功。

## 7. 经济数据模型

每个资产事件以账本为源汇总：

| 维度 | 示例 |
|---|---|
| 时间 | 小时、日、配置版本前后 |
| 资产 | 灵石、物品、秘境机会 |
| 来源 / 去向 | 采集、战斗、秘境、配方、洞府、淬炼、突破 |
| 玩家阶段 | 境界、百艺等级、画像 |
| 数量 / 价值 | 原数量、数值母表基准价值折算 |

核心公式：

```text
Faucet = 系统新生成的灵石与物品基准价值
Sink = 永久销毁的灵石与物品基准价值
Sink/Faucet = Sink / Faucet
Net Issuance = Faucet - Sink
Inventory Days = 当前库存 / 最近 7 日平均消耗
```

MVP 不存在玩家间转移、模拟买卖或 NPC 回收。数值母表基准价只用于统一折算 Faucet / Sink，不代表可成交价格。

## 8. 经济面板

### 总览

- Faucet、Sink、净发行、Sink/Faucet；按日和 7 日滚动。
- 灵石与关键物品的中位持有量、P90、P99。
- 负余额约束失败和账本核对差异。
- 按境界 / 玩家画像的每小时价值。

### 内容健康

- 每个物品的来源、消耗、净增、持有人数、零消耗天数。
- 每个配方完成量、材料成本、基准价值和自产来源比。
- 工具制作 / 装备率和实际回本时长。
- 淬炼等级分布、尝试数、实际成功率与期望偏差。
- 秘境材料和突破材料的库存天数。

### 资源闭环健康

- 每个关键材料的非市场来源数量、来源占比和可达阶段。
- 每个材料的库存天数、零消耗天数和用途点击率。
- 重复装备持有量、装备率和淬炼消耗率。
- 突破材料获得速度与卡点分布。

## 9. 告警阈值

| 指标 | 警告 | 严重 |
|---|---:|---:|
| 账本核对差异 | 任意非零 | 立即停止资产写入灰度 |
| 负库存约束失败 | >0 / 小时 | 持续或可复现 |
| Sink/Faucet 7日 | <0.75 或 >1.00 | <0.60 或 >1.15 |
| Day30 主动价值占比 | <25% 或 >35% | <15% 或 >50% |
| 队列阻塞后无保底 | >0 | 任意导致 >10 分钟无进度 |
| 离线上限超出玩家比例 | >20% | >35% |
| 幂等键相同请求结果不一致 | 任意 | 立即事故 |
| 配置版本未知 | 任意写请求 | 立即拒绝并告警 |

阈值是首版运维线，Alpha 后根据真实分布调整并记录原因。

## 10. 实验规范

- 只实验可逆的 UI、教程顺序、推荐模板和小幅数值。
- 不长期实验会造成不可解释进度差异的掉率或资产公式。
- 每个实验预先写：假设、主指标、护栏、样本、停止条件、最短观察窗。
- 不以“点击更多”作为唯一胜利；规划质量、理解和长期健康优先。
- 实验桶稳定绑定账号，事件记录桶和配置版本。

## 11. 数据质量

- 事件 Schema 进入版本库并自动生成类型。
- CI 校验必填属性、枚举和敏感字段黑名单。
- 每日核对业务表、账本和分析事件的数量 / 金额。
- 客户端事件允许丢失，服务端资产事件不允许静默丢失。
- 时区报表默认 UTC，产品日视图可切 Asia/Shanghai，但事件原始时间不改写。
- 机器人、内部账号和加速测试账号在正式指标中剔除。

## 12. Alpha 决策线

进入更大规模 Alpha 前应同时满足：

- 新手在 10 分钟内理解队列关系的完成率 ≥80%。
- 有意义规划回流率 ≥50%，并呈上升趋势。
- Day 7 均衡玩家达到炼气大圆满附近，Day 10 筑基达成分布合理。
- 秘境主动价值占比主要落在 25%～35%。
- Sink/Faucet 7 日滚动在 0.75～1.00。
- 无资产一致性事故；结算失败可重试并完全恢复。

指标不达标时先修核心循环，不用新增每日任务、红点或限时奖励掩盖问题。
