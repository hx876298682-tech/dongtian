# 《洞天》Web 版 MVP 开发规划 V1

## 目标

在现有 React + TypeScript + Vite Demo 上交付一个可操作的移动端前端闭环，用于验证核心玩法信息架构和首轮用户流程。当前服务端 `global_single_slot_v1` vertical slice 已可联调；UI 不计算结算公式，不伪造奖励，纯视觉 demo 才允许使用与服务端字段一致的 Mock 状态。

核心玩法约束：炼气、战斗、炼丹、炼器、功法研究、法宝研究共用一个主动序列；启动新序列先结算旧序列；炼丹/炼器批次自动入库；灵田种植不占主动序列，成熟后自动入库；legacy building job 不作为当前 UI 入口。

## 本期范围

1. 首页洞天总览：境界、战力、关键资源、修为进度、当前主动序列、灵田成熟状态和最近入库收益。
2. 序列切换：展示当前序列、切换结算结果和新序列状态；不做独立炼丹/炼器后台领取按钮。
3. 探索出征：展示百草谷、黑风谷、赤炎洞等地图；至少一张地图支持出征、结算、成功反馈和奖励入账。
4. 灵田与背包：展示种植、成熟倒计时、自动入库资源，以及资源与装备详情。
5. 成长预览：展示突破条件、当前缺口和至少一个可执行的成长操作；条件不足时不得扣除资源。
6. 移动端优先：底部导航真实切页，桌面端居中预览，常见移动宽度下无内容被底栏遮挡。

## 技术边界

- 保持 React + TypeScript + Vite 和现有 `lucide-react` 依赖。
- UI 首选接入现有 HTTP API；若暂时使用 Mock，字段必须对应 API/服务端状态，不得另造后台队列或领取语义。
- 不修改 `1.0.0-frozen` 数值基线和 `docs/` 中已有设计结论。
- 交互反馈必须对应状态变化，禁止只做静态按钮或虚假的“已成功”提示。

## 里程碑

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| M0 | 清理模板残留，确认启动/构建入口 | `npm run build` 通过 |
| M1 | 首页状态与结算/序列切换 | 资源、修为和当前序列正确变化且不可重复结算 |
| M2 | 探索出征与结算 | 地图选择、进行中、结果反馈、奖励入账 |
| M3 | 背包与成长 | 装备/资源查看，突破条件与成功/不足分支 |
| M4 | 体验验收 | `npm run lint`、移动端布局和关键点击流程通过 |

## 验收用例

- 首次进入首页能看到当前行动和修为进度。
- 完成离线结算或序列切换后，修为、资源、丹药/装备自动更新；重复 settlement 不重复发放。
- 从底部导航进入探索，选择地图并出征；完成结算后能看到结果和奖励，返回首页状态同步。
- 进入背包能看到资源和至少一件装备，并能读取装备详情或类别过滤。
- 进入成长页，资源不足时按钮不可提交且显示缺口；满足条件后突破成功并更新境界。
- 375px 左右宽度下底部导航不遮挡主要操作，按钮和文字不溢出。

## 明确不纳入本期

- UI 之外的新服务端玩法（技能 XP/等级榜单、旧队列迁移等）不在本轮擅自扩展；使用现有 API 的幂等键、CAS 和离线结算契约。
- 真实战斗公式、随机种子回放、掉落保底和经济长期模拟接入。
- PVP、公会、社交、商城、付费货币和后续境界内容。

## 后续进入条件

MVP 通过体验验收后，继续按既有《洞天 Web 版 API 与数据库详细契约 V1.0》做真实 API 联调和移动端视觉验收；不得把 UI Mock 重新解释成后台并行生产或手动领取模型。
