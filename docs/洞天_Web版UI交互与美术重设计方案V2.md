## 一、现状诊断：为什么推翻

| # | 问题 | 具体表现 |
| --- | --- | --- |
| 1 | 大量硬编码假数据 | 属性面板由战力线性推算、固定 3 个装备槽、收获账簿为本地写死条目、地图文案与技能译名硬编码在组件里 |
| 2 | 系统覆盖不足 | 功法研究/功法阁、法宝阁与法宝收藏、秘境与高阶远征、战斗准备与逐秒战斗呈现、装备成长操作（强化/升品/洗练/觉醒）、离线回归结算层、排行榜全部缺失 |
| 3 | 客户端私算收益 | `settleLocalAction` 在浏览器内复算资源产出，违反"客户端不能自行推算旧动作收益"的运行时规则 |
| 4 | 单文件巨石结构 | 1334 行 App.tsx 混杂视图、状态机、API 映射；8 种抽屉塞进一个 ModalSheet 条件分支 |
| 5 | 缺少状态设计 | 行动只有"进行中/空闲"，没有 资源受阻暂停、失败冷却、切换收束 中间态；错误只靠 toast 一闪而过 |
| 6 | 美术未成体系 | 有色板令牌但无材质语言、无品质色规范、无插画策略、无动效规范；视觉停留在"干净的灰绿表单" |

结论：不是在旧 demo 上修补，而是**保留服务端契约与冻结参数，重建整个 UI 层**。

## 二、重设计原则

从玩法结构直接推导，每条都可验收：

1. **行动是唯一主角。** 玩家在整个产品里只维护一个主动序列（单槽互斥），所以全局框架的第一公民是"当前行动条"，任何页面不遮挡它。
2. **回来三问。** 玩家每次打开页面要能在一屏内回答：我在做什么（行动条）、我不在时发生了什么（离线结算层）、下一步做什么（推荐区/入口状态）。这三问的答案优先级高于一切装饰。
3. **UI 不算账。** 一切成本、产出、概率、门槛值来自 bootstrap/catalog 与服务端返回；客户端只做时钟渲染（`carrySeconds`）和格式化。凡涉及公式的预览必须由服务端提供 DTO，否则显示定性描述。
4. **自动入库即终点。** 不存在任何"领取"按钮；生产完成、灵田成熟、挂机掉落都表现为流水记录与资源变动动画。
5. **失败也是信息。** 失败态（超时/阵亡/门槛不足/资源受阻/结算被拒）都是一等公民界面，说明原因、缺口来源和下一步，不虚构奖励。
6. **逐步开放。** 解锁前的建筑/地图以"揭幕卡"形式存在（轮廓 + 解锁境界 + 一句介绍），不隐藏也不剧透数值。
7. **安静的工具感。** 长期挂机产品，动效只出现在状态变化处；任何循环动画不超过一处同屏。

## 三、信息架构

### 3.1 三层模型

```text
┌─────────────────────────────────────┐
│ 全局框架层（永远在场）               │  身份区 · 资源栏 · 行动条 · 底部导航
├─────────────────────────────────────┤
│ 页面层（底部导航切换的一级页）       │  洞府 / 历练 / 行囊 / 道途
│   └ 二级页（全屏推入，栈式导航）     │  建筑·地图·详情·准备·突破…
├─────────────────────────────────────┤
│ 浮层层（按需出现，有序互斥）         │  底部确认面板 > 全屏结算层 > 引导气泡 > toast
└─────────────────────────────────────┘
```

- 一级页之间平级切换（无过渡或 120ms 淡入）；二级页从右侧推入（240ms），可返回；三级浮层自底部上滑。
- 浮层层级严格排序，同一时刻只有最上层可交互；确认面板不可穿透点击关闭以外的遮罩区域。

### 3.2 底部导航与页面树

四tab命名定稿：**洞府 · 历练 · 行囊 · 道途**。（"角色"更名"道途"：该页承载装备构筑、功法收藏、境界路线，是成长决策中心而非信息展示；"背包"更名"行囊"统一仙侠语汇。）


## 四、全局框架规格

### 4.1 总览线框（390 基准宽）

```text
┌──────────────────────────────────────┐
│ ◉云岫  筑基初期        ⟳同步  ⚙      │ ← 身份行 44px
│ 战力 12,480 · 修为 ▓▓▓▓░░ 6,280/9,000 │
├──────────────────────────────────────┤
│ [灵石 1,284][灵草 322][灵矿 96][丹 41]…│ ← 资源栏 32px 可横滑
├──────────────────────────────────────┤
│ ⚡ 当前行动 · 黑风谷斩妖        ✕收功 │
│ 已运行 02:14:36 · 已完成 168 场       │ ← 行动条 ~64px
│ ▓▓▓▓▓▓▓▓▓░░░░░░ 下一场 约18s         │
├──────────────────────────────────────┤
│                                      │
│            页面内容区                │  ← 滚动区
│                                      │
├──────────────────────────────────────┤
│   🏠洞府   🗡历练   🎒行囊   ☯道途    │ ← 底部导航 60px+安全区
└──────────────────────────────────────┘
```

### 4.2 身份区（44px）

- 左：印章头像（首次可自定义名字与印文颜色）；中：道号 + 境界徽标；右：手动同步按钮 + 设置入口。
- 修为微进度条并入身份第二行（窄条，非卡片）；完整修为展示移至洞府首页与道途页。
- 点击头像 → 拉出账号抽屉：玩家ID、版本号 `configVersion`、引导进度、退出登录。

### 4.3 资源栏（32px）

- 六项固定顺序：灵石、灵木、灵草、灵矿、丹药、古修残卷（与 ResourceId 对齐），横滑容纳。
- 每项 = 图标 + 数量；数字变化时滚动跳动一次（200ms），溢出/接近上限时图标变朱砂并附上限角标 `96/100`。
- 长按任意资源 → 浮出简介（用途/主要来源/获取入口深链），数据来自 catalog 资源元数据。

### 4.4 全局行动条 —— 产品的第一公民

五种状态（服务端事实驱动，不允许 UI 臆造）：

| 状态 | 判定来源 | 视觉 | 操作 |
| --- | --- | --- | --- |
| `idle` 神识空闲 | `primaryAction.actionId == null` | 灰底虚线框，文案"神识空闲，去指派一处去处" | 点击展开快速指派面板 |
| `running` 进行中 | actionId 存在且未受阻 | 琥珀点常亮 + 进度条顺滑推进 | "查看详情"跳对应建筑/地图；"收功"停止 |
| `blocked` 资源受阻 | 服务端最后一次结算标记材料不足/库存满 | 朱砂边框 + 缺口摘要"灵草不足，缺 12" | 主按钮"前往补给"深链到炼丹房/仓库 |
| `cooldown` 失败冷却 | `failureCooldownUntil` 未到期 | 冷灰色 + 倒计时"恢复 47s" | 到期自动转 running（若仍有序列）或 idle |
| `settling` 切换收束 | switch/start 请求已发未归 | 进度条呼吸闪烁"旧序列结算中…" | 禁用一切行动按钮 |

细节：

- 计时基于 `startedAt + carrySeconds` 的纯时钟推导，允许倒推已完成的批次数展示（如"已完成 168 场"），但**金额类收益只在服务端结算后由流水展示**，进度条旁不预演数字。
- 斩妖行动额外显示本场击杀进度环与保底计数（古修残卷 `x/y 场必得`，数据取 mapPity）。
- "收功"必须弹二次确认面板：列出预计结算内容物类型（不含数量承诺）、提示"旧行动将先结算"。

### 4.5 底部导航

- 图标风格统一为 1.5px 线性图标 + 选中实心填充；选中态用玉青色 + 顶部 2px 短刻线。
- 行动条若有 blocked/cooldown 状态，对应页面 tab 上显示小朱砂点（例：炼丹受阻点亮"洞府"）。

### 4.6 浮层体系

1. **底部确认面板**（最高频）：选择功法/配方/地块时的参数核对 + 主 CTA，下滑手势可取消。
2. **全屏结算层**：战斗结算、突破成功、离线回归——仪式性时刻，独占视线。
3. **引导气泡**：首日引导的单步提示，锚定到目标元素，只讲一个动作。
4. **toast**：仅用于轻量反馈（同步成功等），关键信息一律走结算层或 inline 提示；禁止连续 toast 堆叠。

### 4.7 离线回归结算层（新增核心页面）

冷启动或 `pendingSettlement` 非空时，首屏之上覆盖全屏层：

```text
┌──────────────────────────────────────┐
│           ☾ 离线修行录                │
│   离开 7 小时 12 分 · 闭关未辍        │
├──────────────────────────────────────┤
│ ✦ 闭关修炼 · 青木长生诀               │
│   修为 +21,360   功法 3 层 → 6 层     │
├──────────────────────────────────────┤
│ ⚔ 百草谷斩妖 · 完成 214 场            │
│   ┌凡剑(精良)┐ ┌皮甲(普通)┐ +2 溢出… │
│   灵石 +8,420  残卷保底 3/30 → 9/30   │
├──────────────────────────────────────┤
│ 🌱 灵田 · 紫云花×2 成熟入库           │
├──────────────────────────────────────┤
│ ✕ 第 37 场阵亡于黑风谷，其后停手      │
│   建议：护体真气不足，见突破清单       │
├──────────────────────────────────────┤
│        [ 收入洞府 ]                   │
└──────────────────────────────────────┘
```

- 分组按行动/事件类型聚合，掉落装备以品质色边框缩略 chips 呈现，超量折叠 `+N`。
- 死亡/停手信息放在最后但必须有，给出真实原因与一条建议（不改玩家序列）。
- 结算被拒场景（时间回拨/重叠区间/revision 过期/重复结算）：明确告知拒绝原因与"不会重复发放"的语义，不给"再次领取"按钮。
- 该层数据结构要求服务端在 offline settlement 响应里返回结构化 summary 分组；若现有 DTO 缺字段，属于前端提出的契约增补需求，不得由前端拼凑。

## 五、页面规格

### 5.2 练功房

- 结构：顶部全局框架不变；页首一行当前修炼概览（功法名、层数/100、每轮修为增量——增量由服务端 catalog 下发的固定值渲染）；主体为功法目录。
- 目录行内容：功法名、品质字印（凡黄玄地天仙五档色）、五行标记、层数、属性方向标签（攻击/防御/生命/速度/五行）、解锁状态。
- 分段筛选：全部 / 攻击 / 防御 / 生命 / 速度 / 五行 / 修为专注（focus_cultivation 若为 proposal 状态，标记"提案中"且不可启动）。
- 点选任意功法 → 底部确认面板：

```text
┌──────────────────────────────────────┐
│ 《烈阳真解》 玄阶 · 火               │
│ 第 6 层 → 修炼中每轮推进层数经验      │
│ ──────────────────────────────────   │
│ 属性收益（示意，见服务端值）          │
│   攻击 +N/层 · 修为 +M/轮            │
│ ⚠ 将结束当前行动「黑风谷斩妖」，      │
│   其已完成场次正常结算入库。           │
│              [ 取消 ]  [ 开始修炼 ]   │
└──────────────────────────────────────┘
```

- 切换警告是**固定组件**（所有会更换主行动的操作复用），有服务端序列时才出现。

### 5.3 炼丹房

- 配方分段（按丹药类别，沿用 catalog recipes 的 actionId=alchemy 集合扩展后自然生长；V1 只有聚气丹一类时单段隐藏分段器）。
- 配方行：丹名、单批耗时、消耗材料（图标×数量，库存不足红色标注缺口）、产出入库去向、当前建筑等级加成文字。
- 确认面板含批次概念位：现行 DTO 无 quantity 字段（运行时口径明确"尚无正式 quantity DTO"），因此 V2 UI **只提供单序列起点**，展示"完成后持续炼制直至材料耗尽或库存满"的说明文案；批量步进器留桩位灰置，DTO 落地后再启用。
- blocked 态行动条与此页联动：显示哪个材料的缺口与"深链去采药/灵田"。

## 六、核心交互流时序

### 6.1 启动/切换行动（所有主行动共用）

```text
选择目标 → 确认面板（含切换警告组件）
  ↓ POST start|switch（Idempotency-Key + expectedRevision）
服务端：先结算旧序列 → 写新序列 → 返回新 revision + settlement summary
  ↓ 成功
行动条切新状态 · 旧收益写流水并触发资源栏跳动动画
  ↓ 失败
按错误码映射（见表 9.2）：CONFLICT → 提示"状态已在他处变更，已为您重新同步"并静默 refresh
```

- 前端禁止在等待期乐观修改经济数值；行动条可先进入 `settling` 态。

### 6.2 离线回归

```text
App 启动 → GET /bootstrap
  ├ pendingSettlement 存在 → 先请求 offline 结算 → 渲染离线修行录层 → 收入洞府
  ├ 失败冷却中 → 行动条 cooldown 态
  └ 正常 → 进入上次停留页（持久化最后 tab）
可见性恢复（visibilitychange hidden>60s）→ 静默 re-bootstrap → 有差异则行动条角标"已结算"一键查看流水
```

轮询策略：前台每 60s 静默 bootstrap；提交写操作后立即刷新一次；不做 WebSocket（V1 不需要）。

### 6.3 突破

条件检查页（可随时进）→ 齐备 → 确认面板（扣料清单）→ POST breakthrough → 成功结算层（节点点亮+解锁揭幕）→ 领域内所有涉及解锁入口自动浮现（建筑揭幕卡转为实体卡，播 320ms 淡入+微光）。

### 6.4 装备成长闭环

掉落 → 流水/结算层 chip → 行囊装备网格 → 详情页 →（对比"当前佩戴"常驻参考列）→ 强化/升品 → 道途页合计属性跳动更新。分解/出售产生的灵石回流 → 资源栏动画闭环。

### 6.5 首日引导映射

沿用新手文档八节点状态机，UI 呈现为一串锚定气泡（每步一个动作）：

1. welcome_seen：欢迎印卡（半透明盖在洞府上）
2. training_started：指向练功房
3. first_settlement_claimed：流水红点
4. first_map_started / completed：指历练·百草谷
5. first_equipment_reviewed：指行囊新装备
6. breakthrough_previewed：指道途境界卡
7. onboarding_completed：金印"初入修行"留存纪念

重复登录只续未完成节点；引导期间不改变任何参数与掉落。

## 七、美术方向：「玄墨青玉 · 山水为幕」

### 7.1 概念定位

在既往三个候选（青绿洞府 / 玄墨修行志 / 幽境锻器录）基础上收敛为一个确定性方向：

> **玄墨为骨** —— 信息层用炭墨、宣纸白、细线分栏做成一本"自动记账的修行手册"，保证长时间、高频次的扫读效率；
> **青玉为韵** —— 以玉青绿作交互强调与生命感；山、云、泉以低饱和青绿插画风仅在场景横幅与地图卡出现，构成"幕布"，绝不压住正文；
> **朱砂点睛** —— 危险、缺口、失败用朱砂；古金只为境界与高品质点睛。三类特殊色各司其职，永不混用。

这使产品同时拥有"工具的可信"与"仙山的意境"，并为日后深色皮肤（夜观星图）预留同一令牌结构的换肤能力。

### 7.4 材质与质感语言

- **纸纹**：`--bg-page` 上叠 2% 不透明度的噪点纹理（base64 内联 SVG feTurbulence 生成，无图片资源）。
- **细线框**：卡片一律 1px `--line` + 4px 圆角；重要卡（建筑/装备详情）用双线框（外 1px + 内嵌 3px 留白再 1px），呼应简牍册页。
- **印章元素**：头像、突破、失败死亡态使用方形朱砂印纹样（CSS 实现，印文白字）；印章只用在这三处，克制即高级。
- **玉石质感**：选中态与成熟态的微光是径向渐变高光（玉青系），不做玻璃拟态模糊。
- **木质符牌**：分段控制器底座做成深墨木条，滑块为宣纸白圆角片。
- 阴影只用两级：`0 1px 2px rgba(28,33,31,.06)` 与 `0 8px 24px rgba(28,33,31,.10)`（浮层）。

### 7.5 图标与插画策略

| 类别 | 方案 |
| --- | --- |
| 功能图标 | lucide-react 线性图标 1.5px，统一玉墨双色（描述可用 accent） |
| 资源/品质图形 | 自绘 24px 双色 icon set（灵石/灵木/灵草/灵矿/丹/残卷 + 六品质印记），几何化"金石篆意"风格，风格 card 内规范化 |
| 器物插画（装备） | placeholder 阶段用"程序化剪影"规范：器型轮廓 SVG × 六槽位模板，叠加品质色描边与对应地图 appearance 纹样参数；正式立绘后按 asset_manifest 替换，id 保持不变 |
| 场景插画 | 洞府横幅 + 各地图卡头，低饱和青绿水彩风（云雾、山影、林泉三层景深）；首发共 3 地图+2 秘境+1 洞府 = 6 张，外包或 AI 生成的交付 spec 附后 |
| 敌人/Boss 表现 | V1 用"名帖"设计：敌名书法字 + 五行印 + 战力刻度，不上怪物立绘（省成本，符合理据：地图挂机多为统计型呈现） |

场景插画交付规格（供内容制作）：比例 16:9 与 4:3 两裁切、SFW、无明显人物面部、统一 300lux 月下青绿调、导出 webp（q80）+ 小尺寸 blurhash 占位。

### 7.6 组件质感规范（核心组件表）

| 组件 | 规格 |
| --- | --- |
| 主 CTA | 玉青实底、白字、按压下沉 1px；禁用为 `--bg-sunken` 底 + `--ink-300` 字 |
| 仪式 CTA（突破/进入秘境） | 古金描边、纸白底、金粉微噪、按下金色泛光一次 |
| 分段控制器 | 32px 高、滑块 180ms cubic-bezier(.2,.7,.3,1) |
| 列表行 | 高 ≥56px、按压整行泛出 4% 玉青 |
| 品质 chip | 文字+左右短划线印痕；immortal 附缓慢（4s）光晕一处 |
| 进度条 | 6px 高、两端方角（石刻凹槽感）、完成的最后一格有 80ms 延迟回弹 |
| 锁定/揭幕卡 | 灰浮雕虚线框 + 中央境界印章 + 一句引言 |

### 7.7 动效规范

统一 token：`--dur-fast:120ms; --dur-base:200ms; --dur-slow:320ms; --ease-out:cubic-bezier(.2,.7,.3,1); --ease-inout:cubic-bezier(.65,0,.35,1)`。

| 场景 | 时长/曲线 | 说明 |
| --- | --- | --- |
| tab 切换 | 120ms 淡入 | 无位移 |
| 二级页推入 | 240ms ease-out | 32px 平移+淡入，返回反向 |
| 底部面板 | 240ms ease-inout 上滑 | 手势跟手至一半以上松手吸附 |
| 资源数字跳动 | 200ms | 滚动递增；同帧合并多次变动 |
| 入库飘字 | 480ms 一次性 | 流水行前"+"淡入上浮 12px |
| 灵田成熟 | 玉光 pulse ×1（800ms） | 之后保持静态角标 |
| 品质高光 rare+ | 一次性 600ms 掠光 | immortal 额外常驻 4s 光晕 |
| 突破成功 | 石刻节点点亮 320ms → 金印盖章 400ms(scale 1.6→1 + 透明度) | 全程 ≤800ms |
| 行动切换收束 | 旧行动条压暗 160ms → 新行动点亮 160ms | 期间输入锁 |
| prefers-reduced-motion | 全局替换为 0ms/opacity 过渡 | 设置里可再降级 |

铁律：同屏循环动画至多一处；进度条推进不用 ease 曲线只随真实时间。

## 八、布局与响应式

- 基准画布 390×844；≥375px 宽均适配，底部安全区 `env(safe-area-inset-bottom)`。
- 移动竖屏优先单列栅格（边距 16px、卡间距 8px、栅格 4 列化心算）。
- 桌面端（≥1024px）：手机画布居中投影放大展示（现有 phone-frame 思路保留，外壳改为「书房案几」氛围底纹而非纯黑背景）；不铺宽屏多栏——内容密度不值得，先保正确的移动体验。
- 触达目标全部 ≥44×44pt；资源栏与导航是唯一横滑区。

## 九、与服务端契约的对齐

### 9.1 数据源纪律

- 一切状态自 `/v1/bootstrap` + `/v1/action-catalog` 派生；两者都是 envelope 包裹（含 `stateRevision/configVersion/serverTime`）。
- 客户端持久层只有一个 store（React Query 或 zustand 均可），保存 `{player, catalog}` 快照 + `lastSyncAt`；所有页面从 store 读数，禁止组件各自 fetch。
- 时间显示统一 `(Date.now() − serverTime偏移)` 校准时钟。

### 9.2 错误码 → 用户语言映射表

| 错误码/HTTP | 界面话术 | 后续动作 |
| --- | --- | --- |
| 409 CONFLICT / stale revision | "洞天状态已在别处更新" | 自动静默 re-bootstrap，然后让用户重试一次 |
| CONTENT_LOCKED | "此道尚未开启" | 操作置灰，附开启条件文案 |
| MATERIAL_SHORT 类业务错误 | 列缺口材料与数量 | 深链补给入口 |
| 幂等冲突 DUPLICATE_REQUEST | "该请求已受理" | 视为成功并刷新 |
| 结算被拒（回拨/重叠/过期/重复） | 如实四选一话术 | 不给重试获利路径 |
| 网络/5xx | "通讯不畅，稍候自动重试" | 行动条显示最后已知状态 + 相对时间 |

### 9.3 内容状态的呈现规则

| status | 呈现 |
| --- | --- |
| `released` | 正常可交互 |
| `proposal_v1` | 可见但明确标"提案试玩/门规未定"徽标；启动入口除非运行时口径放开，否则禁用（当前 herbalism/mining/focus_cultivation 属此类） |
| `content_pending` | 完全不可交互；列表中以揭幕卡占位（名字可隐去，只留类别与境界条件） |
| 未解锁（境界门槛） | 揭幕卡 + 解锁条件 |

## 十、前端工程结构建议

```text
demo/src/ui/            # 全部新 UI（旧的 App.tsx/App.css 删除）
  app/                  # 入口、路由（tab 栈 + 二级页栈，自实现即可，V1 不引 router 库）
  tokens/               # 设计令牌 CSS variables + ThemeProvider
  components/           # 跨页通用组件（ActionBar/ResourceRail/QualityChip/
                        #   SwitchWarnPanel/SettleLayer/SkeletonCard/FmtNum...）
  pages/{cave,journey,bag,path}/   # 每页独立文件，页面内部状态就近
  flows/                # 行动切换/离线回归/突破 的编排 hook（useActionFlow 等）
  api/                  # 现有 client/api.ts 收编，补 type 与错误码枚举
  store/                # bootstrap/catalog 全局快照 + 同步调度
```

- 保留 `src/game`（本地兜底演示模式仍可用其 config 展示 REALMS 元数据，但**线上模式删除断链**：不再 import engine 结算函数）。
- Vite/Tailwind 4 沿用；自定义样式全部经 tokens/，Tailwind 只负责间距布局原子类。
- 验收基线：typecheck/lint/build 通过 + `npm test` 不回归（UI 重构不触碰 server/content/game 测试域）。
