# 《洞天》Stitch 移动端 UI 提示词 V2：梅尔沃放置式框架

## 本版结构结论

本版以用户最新确认的 UI 架构为准，取代 V1 中“修行”作为独立底部导航的方案：

- 顶部固定角色基础信息。
- 顶部固定当前主行动和行为进度条，进入任何二级页面都不消失。
- 底部四个主页面：洞府、历练、背包、角色。
- 洞府只展示四个主要入口：练功房、炼丹房、炼器室、灵田。
- 练功房负责功法选择与修炼；角色页负责装备、修为和突破。
- 参考《梅尔沃放置》的信息结构和放置反馈，不复制其美术、图标或品牌资产。

## 方案一：青绿洞府 · 克制放置 RPG

```text
请为东方修仙深度放置 RPG《洞天》设计一套高保真移动端 Web 游戏 UI，整体信息架构参考 Melvor Idle：固定顶部角色信息、固定当前行动进度条、底部四个主页面。不要复制 Melvor Idle 的素材或品牌，只借鉴它清晰、持续、可扫描的放置游戏框架。生成一套包含主页面和二级页面的完整设计系统，重点展示这些界面：洞府首页、练功房、炼丹房、炼器室、灵田、历练、采药地图、挖矿地图、斩妖地图、背包、角色、突破页面。画布以 390×844 为基准，适配 375px 宽度、底部安全区和桌面端居中预览，所有文字使用简体中文。

产品定位：玩家经营自己的私人洞天，通过选择一项当前行动持续挂机，获得修为、资源、装备、功法和法宝成长，逐步从炼气、筑基、金丹成长到更高境界。核心体验是“随时回来都能看见角色正在做什么、已经获得什么、下一步该进入哪里”，不是社交 MMO、抽卡大厅或商城游戏。

视觉方向：青绿山水、云海、灵泉、木石洞府和玉石器物，做成清润、耐看、适合长时间挂机查看的现代东方游戏 UI。主色为深墨绿、玉青、暖白，辅以朱砂红表示危险，少量古金表示境界和稀有品质。画面需要有真实山水或高质量手绘洞府场景作为局部氛围，但信息区必须保持清楚，不要用大面积背景图压住文字。使用细线、木牌、玉石小组件和轻微纸纹；圆角控制在 4-8px，不做厚重金框、紫蓝渐变、霓虹玻璃拟态和卡片墙。标题使用有书卷气的中文宋体，正文与数字使用高可读黑体，最多两套字体。

全局固定布局必须严格执行：顶部约 132-154px 为 sticky header，包含第一行角色基础信息：角色头像“云岫”、当前境界“筑基初期”、修为/下一境界、战力，以及可以横向滑动的灵石、灵木、灵矿、灵药、丹药、古修残卷资源。第二行是始终可见的“当前行动”区域：行动图标、行动名称、状态、已经进行的时间、预计下一次结算时间或完成次数、实时行为进度条，以及“切换行动”或“查看详情”入口。示例状态可以是“正在修炼·青木长生诀 / 已运行 03:18:20 / 功法层数 +1 / 修为 +70”。无论用户进入哪个二级页面，这个行动条都必须固定在顶部并显示最新状态。底部约 64-72px 固定导航为“洞府、历练、背包、角色”，图标加文字，选中态清楚，不能遮挡滚动内容。

洞府首页是四个建筑入口的总览，不要再设计六个同质建筑卡。上方用一张横向青绿山水洞府场景作背景，下面是四个可点击的功能入口，允许使用 2×2 交互卡，因为它们是实际建筑入口而不是装饰卡：练功房、炼丹房、炼器室、灵田。每个入口必须显示建筑等级、当前状态、预计完成时间或可获得产出。练功房显示“修炼中·青木长生诀”；炼丹房显示当前配方和材料状态；炼器室显示当前打造配方和装备预览；灵田显示 4 块地的种植/空闲/成熟状态。洞府页还要显示一条简洁的“最近自动入库”记录，但不要出现手动领取生产收益。

练功房页面：顶部保持全局行动条，页面主体是功法选择列表。支持“全部、修为专注、攻击、防御、生命、速度、五行”筛选，展示首发功法名称、品质、五行、当前层数/100、每次修炼获得的功法属性、修为增量、预计耗时和解锁状态。按照用户设定，修炼任何功法都能增长修为并获得该功法对应的属性；“修为专注”功法在修为增量上更突出。选中功法后打开底部确认面板，显示属性变化前后对比、当前行动切换提示和“开始修炼”。新行动开始时先结算旧行动，修炼所得自动写入角色状态，不显示领取按钮。条件不足时显示具体缺口并禁用按钮。

炼丹房页面：展示丹药配方分段控制器或纵向配方列表，例如聚气丹、恢复类丹药。每个配方显示材料图标与数量、当前库存、单批耗时、产出数量和当前建筑等级加成。点击配方进入轻量底部面板，使用步进器选择批次数量，清楚标注“消耗材料”和“完成后自动入库”，主按钮为“开始炼制”。炼丹占用顶部唯一主行动，不能与历练、练功、炼器同时进行；切换时提示先结算当前行动。材料不足、库存将满、行动正在进行时都要有明确状态。

炼器室页面：布局与炼丹房保持同一套组件规则，但视觉焦点是装备成品预览。展示武器、四个防具位、饰品六部位，显示装备品质、基础属性、词条槽、材料成本、打造时间和仓库容量。点击某个装备配方后在底部面板显示大尺寸器物插画、属性摘要、所需灵矿/灵木/灵石、库存和“开始炼器”。完成装备直接进入背包或按服务器出口规则自动处理，不能做成手动领取队列。

灵田页面：展示 4 块稳定尺寸的方块田，分别有空闲、已种植、成熟、锁定四种状态。点击单块灵田弹出底部选择面板，列出可种植灵物、成熟时间、预计产量和当前可用地块；点击“种植”后显示倒计时。灵田种植不占顶部主行动槽，成熟后的灵物在下一次结算时自动入库。弹窗必须有关闭、取消和确认反馈，不能让地块因文字变化而跳动。

历练页面顶部先放三个分段控制器：“采药、挖矿、斩妖”。切换分段后，下面展示对应的地图列表。采药页面的地图显示环境插画、可产出草药、挂机时间、产量、解锁境界和当前状态；挖矿页面显示矿脉地图、灵矿产出和风险；斩妖页面显示百草谷、黑风谷、赤炎洞等地图、敌人五行、目标时长、丹药消耗、攻击/防御/生命预览、掉落和保底。选择地图后显示“开始挂机”，开始后顶部主行动立即变成对应行动，并显示行为进度条。斩妖页使用自动战斗逻辑，不出现主动技能按钮；成功、超时、死亡、门槛不足分别有独立结果态，失败不展示虚假掉落。

背包页面：顶部显示容量和资源总量，使用“全部、资源、装备、功法、法宝”分段控制。装备详情采用六部位槽位和六档品质：普通、精良、稀有、史诗、传说、仙器。点开装备显示大图、部位、品质、强化等级、觉醒等级、三个词条槽、锁定状态、来源和属性对比，提供装备、强化、升品、洗练、觉醒、分解、出售等操作，并显示实际消耗和仓库影响。资源详情显示灵石、灵木、灵矿、灵药、丹药、古修残卷的用途与来源。长列表要方便反复扫描，不做满屏装饰卡片。

角色页面：展示角色装备栏详细信息和修为信息。上方是六个装备槽的角色剪影或器物槽位，下方是攻击、防御、生命、速度、命中、闪避和战力等属性摘要；战力只做展示，不替代真实战斗属性和高阶门槛。修为区域展示当前境界、当前修为、下一境界、长线境界路线和突破条件。点击“查看突破”进入独立突破页面：逐项展示修为、灵石、丹药、古修残卷和特殊材料的当前值/所需值/缺口来源；不足时按钮禁用但仍允许查看，满足时显示“开始突破”，提交前展示确认，成功后境界、属性和解锁内容有清晰反馈。

交互和动效：顶部行动条的进度条持续、稳定、低频更新；切换页面不重置进度。进入建筑页面时只做 150-250ms 的内容淡入；选择功法/丹药/装备时用底部面板上滑；开始行动时旧行动先收束为结算摘要，新行动图标点亮；灵田成熟时地块轻微发光并出现“已成熟，自动入库”；突破成功时境界节点和角色属性短暂高亮。长期挂机 UI 要安静、准确、可重复操作。

禁止：不要商城、付费货币、抽卡、PVP、公会、聊天、主动技能栏、暴击、VIP、任务红点海洋；不要把炼丹、炼器或练功设计成并行后台队列；不要出现“领取炼丹收益”“领取炼器收益”；不要将顶部行动条隐藏在二级页面；不要使用大英雄页、SaaS 仪表盘、紫蓝渐变、霓虹玻璃拟态、超大圆角和廉价页游金框。
```

## 方案二：玄墨修行志 · 高密度信息框架

```text
请为东方修仙深度放置 RPG《洞天》设计移动端 Web 游戏 UI，布局参考 Melvor Idle 的放置 RPG 信息架构：角色基础信息固定在顶部，当前行动进度条固定在角色信息下方，底部只有“洞府、历练、背包、角色”四个主页面。只借鉴信息层级和放置反馈，不复制 Melvor Idle 的视觉资产。请生成一套可落地的高保真多页面 UI，包含洞府、练功房、炼丹房、炼器室、灵田、历练三分段页面、背包、角色和独立突破页面。基准画布 390×844，兼容 375px 宽度和安全区，中文界面。

视觉命题：一本持续自动记账的玄墨修行志。以黑漆木、冷白宣纸、玉简、铜印、朱批和简洁山河舆图为材质，但保持现代游戏的快速扫描感。主色为炭黑、墨灰、冷白、青玉绿，朱砂红用于危险和错误，古金只用于境界和高品质。避免整页米黄色、过度书法、粗重金边和复杂背景纹样。使用紧凑栅格、细线分栏、账本行项目、分段控制器和轻量底部弹窗；面板圆角 2-6px，不要卡片堆叠。

固定框架：顶部 sticky header 第一行显示头像、角色名“云岫”、境界、当前修为、战力和横向资源栏；第二行固定显示“当前行动”及一条明确进度条，包含行动名称、已运行时间、预计间隔/完成次数、当前产出和“切换行动”。示例：“炼丹·聚气丹 / 12 批完成 / 00:18:20 / 产出自动入库”。切换行动前要提示会先结算旧行动。底部固定四项导航“洞府、历练、背包、角色”，进入任意建筑或详情页后顶部两行都不消失。

洞府页采用“洞天账册”总览，主要入口只有练功房、炼丹房、炼器室、灵田。四个入口可以是清晰的 2×2 交互单元，分别展示等级、当前行动关联、产出和状态；不要添加第五、第六个并行建筑入口。页面上方用小型洞府舆图作氛围，页面下方用账本行展示修为进度、灵田成熟时间和最近自动入库变化。

练功房页像功法目录。用分段控制器筛选“全部、修为专注、攻击、防御、生命、速度、五行”，每行显示功法名称、品质、五行、层数/100、修炼一次获得的功法属性、修为增量、时间和选中状态。产品设定为任何功法都增长修为并增加对应功法属性，修为专注功法在修为收益上更高；这类数字先按示例状态展示，不能自行发明正式数值。点击行打开底部确认页，显示选择前后对比和“开始修炼”。

炼丹房页像配方账簿，按丹药类别分段，显示配方、材料当前/需要、单批耗时、批次数量步进器和完成后自动入库。点击“开始炼制”后该炼丹序列成为顶部唯一主行动，不能与练功、历练、炼器并行。炼器室页沿用配方账簿结构，右侧或下方提供装备成品预览和六部位标签，显示武器、四防具、饰品、品质、词条槽、材料成本、仓库容量和自动入库规则。

灵田页用四个边长固定的方形地块组成田契网格，不用不稳定的自由插画布局。每块地有空闲、种植中、成熟、锁定状态。点击地块打开底部弹窗，选择灵物、查看成熟时间和产量，然后确认种植。灵田不占顶部主行动槽，成熟在下一次离线/行动结算中自动入库。弹窗中明确当前地块、选择的灵物和确认结果。

历练页顶部为三个分段控制器“采药 / 挖矿 / 斩妖”。采药与挖矿显示若干地图的产出、耗时、资源类型、解锁状态和“开始挂机”；斩妖显示百草谷、黑风谷、赤炎洞和秘境节点，选中后展示五行、敌人、目标时长、丹药预算、攻击/防御/生命、掉落和保底。开始挂机后只改变顶部当前行动和进度条。斩妖中的战斗是自动逐秒状态机，表现生命、护盾、状态、自动丹药和结算日志，不提供主动技能按钮。失败页面只显示真实失败原因和冷却，不编造奖励。

背包页像收藏档案，分为资源、装备、功法、法宝，显示容量、筛选和排序。装备详情展示六部位、六档品质、强化、升品、洗练、锁定、觉醒、词条、来源与属性前后对比。角色页是玩家状态中心：上方六件装备槽，下方角色属性和修为；点击修为区域进入突破页面。突破页采用逐项核对清单，显示当前值、需要值、缺口来源，条件不足时禁用按钮且不扣除资源，满足时显示“开始突破”。

动效只用于状态变化：账册行从淡墨变为实色、进度条顺滑推进、底部弹窗轻微上滑、行动切换时先展示旧行动结算再点亮新行动、突破成功时盖下一个简洁朱印。页面必须像工具一样可靠，不能做成慢速阅读器。

禁止商城、付费货币、抽卡、PVP、公会、聊天、主动技能、暴击、VIP、任务红点、后台并行队列、手动领取生产收益、失败掉落、满屏米黄纸张和粗金边。
```

## 方案三：幽境锻器录 · 暗色刷宝放置框架

```text
请为东方修仙深度放置 RPG《洞天》设计一套偏硬核的移动端 Web 游戏 UI，整体布局参考 Melvor Idle：顶部永久显示角色基础信息和当前行动行为进度条，底部仅有洞府、历练、背包、角色四个主页面。不要复制 Melvor Idle 的品牌和素材。请生成高保真多页面方案，包含洞府总览、练功房、炼丹房、炼器室、灵田、历练中的采药/挖矿/斩妖、背包、角色和突破页面。使用 390×844 画布，兼容 375px、底部安全区和桌面端居中预览，界面全部使用简体中文。

视觉命题：危险远征、灵脉开采与装备锻造。使用黑石洞府、雨夜山门、灰绿灵火、朱红封印、铜器、磨损玉石和局部锻造火星，吸收暗黑刷宝游戏的重量感，但保持东方修仙的材质与秩序。主色为近黑石色、灰绿、骨白；青玉绿表现可用和生命，朱红表现危险，古金表现境界和高品质，火橙只作为锻造细节。不要全黑、赛博霓虹、西方城堡和大面积玻璃拟态。所有信息面板 2-6px 小圆角、薄边框，列表和分段控制器优先于卡片墙。

固定顶部必须成为全局操作锚点。第一行展示“云岫”、头像、境界、修为、战力和灵石/灵木/灵矿/灵药/丹药/古修残卷；第二行展示唯一当前主行动，例如“黑风谷斩妖 / 已运行 04:12:36 / 已完成 168 场”，配一条有明确起点、当前进度和终点的行为进度条，并显示预计下一场时间、当前消耗和“切换行动”。进入任何页面都保留该区域。底部四个主导航固定为洞府、历练、背包、角色，选中态使用局部玉光或金属刻痕，点击区至少 44px。
```
