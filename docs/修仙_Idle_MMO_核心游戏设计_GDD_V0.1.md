# 《暂定名：洞天 / 修仙 Idle MMO》核心游戏设计 GDD V0.1

**版本：** V0.1  
**文档类型：** 核心游戏设计文档 / Core Game Design Document  
**项目阶段：** 概念验证 → MVP 立项前  
**设计目标：** 建立一款以“闭关规划、修仙百艺、玩家经济、境界突破、异步多人”为核心的长期在线修仙放置 RPG  
**参考方向：** 借鉴《Milky Way Idle》的时间经济、技能成长、行动队列和玩家市场底层逻辑，但不做修仙换皮  
**本版重点：** 系统结构、玩家体验、内容解锁、经济闭环、MVP 范围  
**本版暂不锁死：** 具体 XP、产出、掉率、装备数值、市场价格、强化概率

> **2026-08-16 MVP 范围修订：** 本文关于坊市、模拟市场、NPC 回收和玩家交易的内容只代表长期产品方向，不进入当前 MVP 开发。首版先完成闭关、生产、装备、秘境、洞府、淬炼和筑基游玩闭环；市场只保留 `feature.market`、模块名与未来 API 命名空间。所有关键资源必须具备非市场来源。具体实现以开发前文档包 DEC-029 和《Luna 代码开发实施规格 V1.0》为准。

---

# 0. 一句话定义

> **这是一款“玩家安排修士人生”的异步多人修仙放置 RPG。**

玩家不是单纯操控一个战斗角色，而是经营一名修士的长期修行人生：

```text
闭关修炼
采集天材地宝
修习百艺
炼丹炼器
历练秘境
经营洞府
参与坊市
加入宗门
突破境界
```

游戏世界即使玩家下线，也持续运转。

# 1. 核心产品定位

## 1.1 类型

```text
修仙
+
Idle / Incremental
+
资源管理
+
生产经营
+
RPG Build
+
玩家市场
+
异步 MMO
```

## 1.2 不是什么

本项目不做：

- 传统“战力数字挂机手游”
- 自动推关 + 抽卡养角色
- 强日常打卡 MMO
- 纯单机修仙模拟器
- 需要玩家长期在线操作的战斗游戏
- 纯文本 MUD
- 单纯《Milky Way Idle》修仙换皮

## 1.3 产品核心差异

真正的差异化是：

# “修仙世界中的时间经营”

玩家玩的不是：

```text
今天能打多高伤害
```

而是：

```text
接下来 8 小时，我应该让自己修炼、采药、炼丹，还是去秘境历练？
```

# 2. 核心设计支柱

整个项目所有功能都必须服务以下 6 个支柱。

## 2.1 时间规划

玩家通过“闭关计划”安排未来行为。

## 2.2 境界成长

境界是游戏最顶层主线，同时承担系统复杂度门槛。

## 2.3 修仙百艺

生活技能不是附属，而是与战斗平行的正式成长路径。

## 2.4 玩家经济

坊市让采集、生产、战斗玩家互相依赖。

## 2.5 异步多人

多人内容绝不要求玩家固定时间上线。

## 2.6 长期身份

玩家最终成为：

```text
剑修
丹师
器师
商人
采集者
宗门骨干
收藏家
秘境玩家
```

而不是所有人走向同一个“战力终点”。

# 3. 核心玩家幻想

玩家应该逐渐获得以下体验：

## 初期

> “我是一个刚踏入修仙界的无名散修。”

## 中期

> “我开始有自己的修行路线和谋生方式。”

## 筑基后

> “我已经真正成为修士，并形成了自己的专业。”

## 金丹后

> “我在这个修仙世界里有资产、有身份、有关系。”

## 元婴以后

> “我不再亲力亲为，我开始管理洞府、分身、宗门和长期资源。”

# 5. 时间系统

## 5.1 时间是核心货币

所有行为都具有：

```text
基础耗时
```

玩家真正优化的不是单次产量，而是：

```text
修为 / 小时
经验 / 小时
资源 / 小时
灵石 / 小时
```

## 5.2 离线原则

基础离线进度目标：

```text
8～12 小时
```

设计目标：

> 普通玩家每天早晚各查看一次，就不会损失主要成长。

## 5.3 不做强制频繁上线

禁止：

- 每小时领奖
- 固定整点 Boss
- 每两小时收菜
- 离线收益必须手动领取才能继续
- 必须实时参加宗门活动

---

# 6. 闭关计划 Action Queue

闭关计划是整个项目完成度要求最高的核心系统。

## 6.1 基础结构

```text
当前行动
↓
行动 2
↓
行动 3
↓
无限保底行动
```

例如：

```text
百草谷采药 × 2小时
↓
炼制聚气丹 × 200
↓
温养青锋剑 × 1小时
↓
黑风谷历练
↓
无限修炼
```

## 6.2 玩家真正的操作

玩家不反复点击：

```text
采药
采药
采药
```

而是：

```text
制定未来计划
```

## 6.3 早期队列

炼气期：

```text
顺序执行
固定数量
固定时长
无限执行
```

## 6.4 筑基后条件队列

加入简单条件：

```text
采药
直到 青灵草 ≥ 500

↓

炼丹
直到 聚气丹 ≥ 100

↓

修炼
```

## 6.5 金丹后自动补给

例如：

```text
若聚气丹 < 20
→ 自动炼制

若灵草 < 100
→ 自动从坊市购买
```

## 6.6 元婴后高级自动化

通过：

```text
洞府管家
分身
策略模板
```

开放：

- 并行行动
- 自动采购
- 自动补给
- 自动出售
- 自动切换行动
- 条件策略

成长不仅让数字变大，还让管理越来越轻。

# 8. 境界的设计职责

境界不是单纯属性倍率。

一个境界负责四件事：

```text
1. 世界观身份
2. 长期主目标
3. 内容 Tier
4. 系统复杂度门槛
```

因此：

> “我是什么境界”必须比“我多少级”重要。

---

# 9. 境界内部成长

建议采用：

```text
初期
中期
后期
大圆满
```

例如：

```text
炼气初期
炼气中期
炼气后期
炼气大圆满
↓
筑基
```

让玩家同时拥有：

```text
短期小阶段
+
长期大突破
```

---

# 10. 突破条件

突破不能只是修为满。

基本公式：

```text
修为
+
关键丹药
+
身体 / 神识条件
+
突破材料
+
阶段挑战
```

例如筑基：

```text
修为达到大圆满
筑基丹 ×1
灵髓 ×3
经脉达到要求
↓
筑基试炼
```

但避免过多随机失败。

第一版建议：

> 玩家准备充分后，突破应具有可预期性。

随机性主要用于：

```text
额外品质
突破异象
特殊天赋
```

而不是让玩家几天投入直接归零。

---

# 11. 境界突破奖励原则

每一次大境界突破必须提供：

# 机制型奖励

而不是纯属性。

例如筑基：

- +1 闭关队列槽
- +1 丹药药力槽
- 解锁二阶百艺
- 解锁筑基地图
- 解锁正式秘境
- 解锁第二功法槽
- 解锁洞府升级
- 解锁高级坊市信息
- 解锁宗门正式加入

# 64. 经济设计原则

## 64.1 任何资源必须至少有两个需求方

防止：

```text
单一配方没人做
→ 资源归零
```

通过：

```text
消耗品
洞府
宗门
高级配方
炼化
```

持续需要旧材料。

## 64.3 新版本优先复用旧资源

避免：

```text
T1～T10 全部垃圾
```

# 90. V0.1 最终设计宣言

> **我们不是在做一个“修仙题材的挂机游戏”。**
>
> 我们要做的是：
>
> **一个玩家用时间、资源和选择经营自己修仙人生的长期世界。**

这个世界里：

```text
剑修可以靠秘境成名
丹师可以靠坊市致富
器师可以打造全服追求的法器
商人可以通过价格变化积累财富
散修可以独来独往
宗门玩家可以参与长期建设
```

所有这些玩家：

共享同一个经济系统。

而：

# “闭关”

让它成为一个真正适合现代玩家生活节奏的修仙世界。

# 附录 B：系统设计检查问题

以后新增任何系统前，必须回答：

```text
1. 这个系统属于哪个境界？
2. 玩家为什么需要它？
3. 它增加了什么新的决策？
4. 它和现有哪个系统形成循环？
5. 它创造还是消耗资源？
6. 它是否增加市场需求？
7. 玩家不使用它还能否玩？
8. 它是否要求实时上线？
9. 它会不会让 UI 更乱？
10. 它最终把玩家送到哪个下一目标？
```

如果无法回答：

暂时不加。
