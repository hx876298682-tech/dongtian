# 《洞天》数值参数规范

## 参数字段

`洞天数值参数表.csv` 是洞天最终数值设计的登记入口。每个参数必须有：

- `parameter_id`：稳定、唯一、英文小写点分隔 ID。
- `domain`：`core`、`growth`、`breakthrough`、`building`、`recipe`、`economy`、`combat`、`map`、`dungeon`、`loot` 或 `offline`。
- `value` / `unit`：最终值和单位；未确定时保持空，不用 0 代替。
- `value_type`：`constant`、`target`、`scalar`、`cost`、`probability`、`policy` 或 `derived`。
- `status`：`confirmed`、`pending_design`、`proposal_v1`、`frozen_v1`、`derived`、`validated` 或 `unknown`。
- `source`：洞天 GDD、设计决策或计算产物。
- `reference_source`：Melvor 逆向产物，只作为参考证据。
- `formula_or_rule`：计算公式、边界或取整规则。
- `rounding`：事件取整规则；未定时不得猜测。

## 值的生命周期

```text
Melvor raw/reference
        |
        v
洞天换算参数
        |
        v
洞天设计目标
        |
        v
洞天最终值
        |
        v
成长/经济/战斗验证
```

Melvor 的原始值不得直接覆盖洞天最终值。所有换算都必须进入参数表，并保留参考来源和 `realm_scale`、`breakthrough_scale` 等系数。

## 单位规则

- 时间内部统一使用秒；展示层可以换算为分钟、小时或天。
- 概率统一使用百分比 `0-100`；最终随机事件必须另记是否按整数百分比、浮点概率或权重抽取。
- 连续成长值使用整数 XP/修为点；显示层可以格式化，但存储层不使用字符串缩写。
- 资源、物品和货币数量默认是非负整数；允许小数时必须在 `rounding` 明确说明。
- 速度、倍率和 Modifier 使用 ratio 或 percent，不能混用。
- 枚举/布尔/事件开关类参数可以使用 `enum`、`boolean` 或 `event` 作为 `unit`；枚举值保留原文，不强行转数值。

## 设计状态规则

- `confirmed`：来自 GDD 或固定单位定义，当前无需平衡决策。
- `pending_design`：已确定参数用途，但尚未决定洞天最终数值。
- `proposal_v1`：当前数值设计提案，已满足目标约束但仍需资源/战斗/离线验证和后续调参。
- `frozen_v1`：已通过当前 V1 全量审计并纳入冻结候选；只允许通过变更号和完整回归审计修改。
- `derived`：由其他已确定参数计算得出。
- `validated`：已经通过成长时间、资源闭环或战斗效率验证。
- `unknown`：规则或运行时语义没有证据，不能写入最终公式。

## 当前首批参数

已固定的只有时间单位、概率边界和 GDD 的三个成长目标：24 小时、48 小时、168 小时。境界修为、突破资源、建筑速度、战斗属性、掉落权重和离线规则均保持 `pending_design`，等待后续数值设计阶段落定。
