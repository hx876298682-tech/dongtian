# 《洞天》玩法设定对照审计 V1

## 审计范围

本文件只核对用户提出的目标玩法与当前服务端/前端现状，不修改 UI、服务端 runtime、冻结参数或内容包。

当前权威基线：[洞天当前运行时口径V1](洞天当前运行时口径V1.md)。当前服务端行动模型为 `global_single_slot_v1`，前端仍是独立本地 Mock。

## 总结

结论不是“全部满足”。当前已成立的是单行为槽、序列切换结算、功法/采集 vertical slice、可选丹方/器方、斩妖地图、灵田逐块成熟、背包状态和突破服务端链路；正式内容包、平衡参数和 UI 联调仍未闭合。

## 当前可以进入的玩法闭环

1. 选择炼气、斩妖、指定功法、采药、挖矿、指定丹方或指定器方中的一个主动序列。
2. 启动新序列时先结算旧序列，收益自动写入资源/装备库存。
3. 灵田按批次种植并等待成熟，不占主动序列。
4. 通过离线结算查看修为、资源、斩妖掉落和灵田成熟收益。
5. 停止主动序列后检查突破条件并执行突破。

## 不能宣称已经完成的内容

- Melvor 风格的多技能竞争已具备服务端 MVP 状态和排行榜类型，但正式技能等级曲线、地图池、产出平衡和 UI 仍未完成。
- 当前采药/挖矿各有一个 proposal 地图，不能宣称正式三类地图内容包已经完整。
- 旧批次灵田仍保留兼容路径；新逐块地块与 `plantId` vertical slice 已实现，但正式种子成本/不同灵物产出尚未进入冻结内容包。
- 当前前端仍是 Mock，不能用现有页面证明服务端玩法已经被正确展示或可真实游玩。

## 后续进入开发前必须冻结的输入

1. 功法 action 的 `techniqueId`、修炼经验、修为收益、属性成长、等级/层数上限和榜单规则。
2. 丹方/器方对象池、选择 DTO、材料成本、产出数量和炼器装备模板 binding。
3. 灵田正式 `plantId` 内容、种子来源/成本和不同灵物产出；逐块状态、成熟时间、重复种植和离线结算语义已完成 vertical slice。
4. 采药/挖矿地图分段、资源表、行动间隔、技能成长和失败/耗材规则。
5. 角色页突破是否由客户端先 stop/settle 再调用 breakthrough，还是新增组合 mutation。

状态：`audited / feature_gaps_before_ui`。
