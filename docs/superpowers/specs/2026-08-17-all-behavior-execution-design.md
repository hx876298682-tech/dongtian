# 百艺全行为执行设计

## 目标

让百艺下的可执行行为拥有统一的“选择行为 → 查看产出 → 点击开始 → 顶部进度反馈”体验。采药与采矿按地图区域组织，炼丹与炼器按工坊分类组织；所有执行仍由服务端行动目录与挂机队列负责。

## 百艺子菜单

- 采集 / 采药：`/craft/herbalism`，地图区域 → 草药行动。
- 采集 / 挖矿：`/craft/mining`，地图区域 → 矿石行动。
- 炼丹：`/craft/alchemy`，炼丹分类 → 丹药配方。
- 炼器：`/craft/forging`，炼器分类 → 工具、武器、防具等配方。

“百艺”主菜单下直接展示以上子菜单；技能等级区块只展示等级数据，不承载行为入口。

## 统一行为模型

- 行动目录是权威来源：`enabled`、`unlocked`、`unlock_state`、`allowed_queue_modes`、`outputs`、`inputs`、时长和经验全部来自 API。
- 页面筛选由行为定义提供 `actionTags` / `skillId`，不复制服务端解锁判断。
- 可执行条件必须包含 `INFINITE` 队列模式；不可执行行动展示锁定、材料不足或模式不支持原因。
- 点击开始写入单条无限队列；409 时重新读取队列版本并重试一次；暂停队列自动恢复；成功后失效行为页、洞府首页和顶部进度查询。
- 所有页面使用统一的加载、错误、空态、不可用态和成功反馈组件/样式。

## 分类展示

- 采药、挖矿：使用已有六个区域目录；每个区域只显示匹配 tag 的行动，空区域保留并显示“暂无可执行行动”。
- 炼丹：按配方 `tags` 分组为基础丹药、突破丹药、战斗/恢复丹药等，卡片显示输入材料和产物。
- 炼器：按输出物品 tag 分组为工具、武器、防具；卡片显示输入材料和产物。

## 验收标准

1. 百艺下直接看到采药、挖矿、炼丹、炼器四个子菜单，技能等级区没有行为入口。
2. 四个页面均能从 API 行动目录展示真实可执行/锁定状态和材料/产出。
3. 任一可执行行动点击后都会进入现有挂机队列，顶部进度栏立即刷新。
4. 页面不新增本地行为计时，不伪造未在行动目录中的资源或配方。
5. 新增行为适配器、通用页面、导航层级和队列触发测试；Web 全量测试、typecheck、lint、build 通过。
