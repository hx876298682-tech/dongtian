# 洞天 UI 设计稿适配方案

## 目标

将 `ui 设计图/` 中 12 张桌面设计稿落地到现有 React 游戏工作台，统一视觉壳层、页面密度和交互反馈，同时保留当前真实 API、队列、导航、错误态和无权限态行为。

## 视觉系统

- 画布：墨黑 `#0b1110`，叠加极轻的纸张噪点和铜绿暗纹；不使用渐变光球。
- 导航：左侧固定窄栏，青绿活动底色，金铜选中线；桌面默认展开，窄屏改为底部导航。
- 顶栏：洞天标题、挂机进度、资源摘要和角色入口按单行高密度排布。
- 内容区：青绿色工作区，细铜线分割；页面标题、状态、操作和数据采用旧纸白、灰青和金铜三层文字。
- 表面：取消大圆角和厚阴影；常规区域使用 1px 线框与内间距，只有对话框保留小圆角。
- 字体：中文系统无衬线作为正文，标题用窄字重和较高字距，避免引入外部字体依赖。

## 壳层与页面映射

壳层统一应用于洞府、修炼、突破、百艺、采药、挖矿、炼丹、炼器、历练、角色、背包和设置。各页面继续复用原有 feature 组件和查询逻辑，仅通过统一 class token 改变结构表现。洞府页面作为首屏视觉锚点，维持设施列表、详情和建造状态三栏；其它页面保持现有列表/详情/编辑工作流。

## 响应式与交互

- `>= 1440px`：左导航、中央工作区、右角色栏三栏；中央区域优先保证可读宽度。
- `900px - 1439px`：右角色栏变为可打开的 overlay，主内容保持两栏或单栏自适应。
- `< 900px`：顶部资源折行，左导航收为底部横向导航，内容卡片单列；操作按钮保持可点击尺寸。
- 保留挂机进度的线性更新、暂停/恢复、加载/错误/空/锁定状态和键盘可达性。

## 验证标准

1. `pnpm --filter @dongtian/web typecheck` 通过。
2. `pnpm --filter @dongtian/web build` 通过。
3. 启动 Vite 后检查 `/dashboard/cave`、`/cultivation`、`/craft`、`/expedition`、`/character`、`/inventory`、`/settings`，确认壳层与设计稿同向且无横向溢出。
