# 《洞天》当前运行时口径 V1

> 这是当前服务端与 UI 联调的最高优先级玩法说明。若其他旧文档或 proposal 与本文冲突，以本文、服务端代码和 API/数据库契约为准。

## 版本

- action model：`global_single_slot_v1`
- active release：`1.0.0-frozen`
- 当前高阶模式：`signature_only_v1`
- UI：移动端优先、单页固定视口，UI 不计算结算公式

## 主动序列

每个玩家只有一个主动序列。以下动作互斥，不能并行：

- 炼气：`training`
- 普通地图：`bai_cao_valley`、`black_wind_valley`、`red_flame_cave`
- 秘境/高阶远征：已登记的 dungeon/high-tier action
- 炼丹：`alchemy` + `recipeId`（旧 `alchemy_basic` 兼容）
- 炼器：`forge` + `recipeId` + `equipmentTemplateId`（旧 `forge_basic` 兼容）
- 功法研究：`technique_research`
- 法宝研究：`treasure_research`

启动不同动作时，服务端先结算旧序列，再提交新序列。客户端不能同时保存多个进行中的主动动作，也不能在 UI 层自行推算旧动作收益。

## 生产与入库

- 炼丹/炼器按所选配方的完整批次模拟；输入不足不扣半批、不产生负库存，序列在无法继续时结束。
- 炼丹产出直接写入资源状态；炼器按已校验模板通过正式 writer 生成装备实例并直接入库，不需要手动领取；未知 recipe/template 必须 fail-closed。
- 生产结果与 settlement、CAS、幂等和审计在同一服务端结算边界内处理。
- 当前尚无正式 `quantity/remainingQuantity` 主动序列 DTO；不要自行添加预排队或批量领取语义。

## 灵田

- 灵田不占主动序列。
- 使用 `POST /v1/buildings/spirit_farm/plant`，字段为 `plots` 和 `expectedRevision`，需要 `Idempotency-Key`。
- 状态字段为 `planted_plots`、`planted_at`、`mature_at`。
- 成熟后由下一次离线结算请求自动入库并清空批次；当前没有后台 scheduler。
- 旧安装 `planted_plots IS NULL` 代表兼容连续灵田模式，不得把它迁移成新玩家的显式种植记录。

## 主动功法与采集 Proposal

- `technique_training` 通过 `techniqueId` 选择功法，结算同时增加修为和对应功法技能/属性进度；`focus_cultivation` 为 MVP proposal 专注修为目标。
- `herbalism + herb_grove` 和 `mining + ore_mine` 通过 `mapId` 选择采集地图，结算直接入库资源并增加对应技能 XP。
- 上述新增技能参数仍为 proposal，不得当作 frozen 平衡输入；详情见 `洞天主动技能与采集玩法ProposalV1.md`。

## Legacy 边界

`POST /v1/buildings/{buildingId}/jobs` 和 `building_job` 表只为旧安装读取、回放和迁移兼容保留。在 `global_single_slot_v1` 下：

- 不允许新建炼丹/炼器 legacy queue。
- legacy queue 不被离线结算被动执行。
- 不在没有产品决策的情况下猜测取消、退款、冻结或资源返还。
- 新 UI 不得把 legacy queue 显示成当前进行中的生产序列。

## 互斥活动

秘境和高阶 Boss attempt 与主动序列互斥。活动 attempt 进行时不能启动炼气、地图、炼丹、炼器或研究；主动序列进行时不能启动新的 attempt。

## 当前明确未冻结

- 丹道/炼器技能 XP、等级上限、排行榜字段和排序规则
- 主动生产的正式数量 DTO
- legacy building job 取消/返还/冻结迁移方案
- FI-02 清风正式参数、FI-04 `full_v1`、随机事件正式公式与迁移语义
- 正式装备实例模板的完整首发内容与地图 binding

这些缺口必须先由产品输入或正式 release 关闭，不能用 proposal、fixture 或 UI 状态猜测实现。
