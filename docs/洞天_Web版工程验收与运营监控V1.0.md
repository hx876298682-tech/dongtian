# 《洞天》Web版工程验收与运营监控 V1.0

## 目的

本文件定义把 `1.0.0-frozen` 数值基线接入真实服务时的工程验收、发布、回滚和运营监控边界。工程验收失败时只能阻止发布，不能通过修改数值绕过问题。

## 发布前验收层级

### L0：配置完整性

- 参数表 Schema 校验通过：`1142` 行、`12` 列、无重复 ID。
- 内容包 manifest 的版本和 SHA-256 与 `1.0.0-frozen` 一致。
- 所有内容对象 ID 唯一，所有参数引用存在。
- `content_pending` 对象不会进入可解锁、掉落或战斗列表。
- 普通地图、秘境、装备六部位、建筑和配方的枚举集合完整。

### L1：纯函数回归

- 版本校验器和参数表 Schema 校验器通过。
- 属性汇总、命中、防御、攻击间隔、五行、战力和丹药公式通过固定样例。
- 三张地图目标击杀时间和三档秘境 Boss 目标时间通过。
- 掉落品质、古修残卷保底、秘境四类保底和装备出口通过随机样本。

### L2：状态机回归

- 主动序列切换先结算未结算区间；灵田种植批次不被清空，legacy building job 不作为当前生产来源。
- 离线最多结算 24h，60s 批处理和余数结转正确。
- 普通地图首次失败停止后续战斗；秘境/Boss 失败不发奖励、不扣失败场丹药、不推进保底。
- 高阶门槛外只阻断 Boss 独立奖励，资源供给继续。
- 突破、装备成长、仓库出口和库存上限均无部分提交。

### L3：并发与故障回归

- 同一 `settlement_id` 并发请求只能提交一次。
- 相同 `expected_revision` 的跨设备请求只有一个成功，其他返回 `STALE_REVISION`。
- 数据库事务失败时库存、保底、余数、随机状态和审计记录全部回滚。
- Redis 重启不丢失权威状态，不导致重复结算。
- 服务重启后可从 `pending` 结算记录恢复或安全拒绝。
- 时间回拨、重叠区间和配置版本不匹配有明确错误码。

### L4：体验验收

- 新玩家能完成首次练功、百草谷、装备查看、突破预览。
- 离线收益结果与服务端摘要一致。
- 失败、门槛、丹药不足、仓库满载和冷却状态有可理解提示。
- 桌面端和移动端不出现奖励、资源或结算状态互相覆盖。

## 运行指标

### 结算可靠性

- `settlement_success_total`
- `settlement_rejected_total{reason}`
- `settlement_duplicate_total`
- `settlement_stale_revision_total`
- `settlement_duration_ms`
- `settlement_pending_age_seconds`

### 经济安全

- 资源增量和消耗按 `resource_id` 统计
- 库存达到容量比例（P50/P95/P99）
- 溢出数量和溢出资源类型
- 负库存校验失败次数
- 突破、装备升品、觉醒、洗练的消耗/成功次数
- 地图/秘境成功、失败、门槛阻断和冷却次数

### 内容和战斗

- 各活动平均/分位通关时间
- 丹药消耗与冻结预期偏差
- 掉落品质、保底触发和对象池分布
- `timeout`、`player_dead`、`gate_blocked` 比例
- 战斗日志哈希缺失或无法回放次数

## 报警规则

以下任一情况必须阻止自动扩容或内容发布并人工复核：

- 负库存、重复 settlement 发奖或 revision 倒退。
- 结算回滚率超过基线，或 `pending` 记录超过允许处理窗口。
- 任一活动的掉落分布显著偏离冻结样本区间。
- 资源/hour、丹药净流量或突破成功率出现非配置变更导致的漂移。
- 内容包出现未知参数 ID、重复对象 ID 或 `content_pending` 可达路径。
- 配置版本和结算记录版本不一致。

具体阈值由压测基线确定；在阈值确定前只允许告警，不自动调数值。

## 配置发布与回滚

```text
生成内容包 + 参数 manifest
 -> 离线 Schema/全量审计
 -> 只读预发布环境
 -> 固定种子回归
 -> 小流量灰度
 -> 监控经济/结算/战斗指标
 -> 全量发布
```

回滚只回滚配置引用和代码版本，不重算已经提交的结算。历史状态继续使用写入时的 `config_version`；发生不可逆数据问题时使用人工补偿工具，并记录审计事件。

## 权限与安全边界

- 客户端不能写资源、战斗结果、保底、随机状态或排行榜分数。
- 管理员补发、扣除和修复必须使用独立权限、双人审批或审计记录。
- 排行榜使用已提交快照，不能从客户端传入战力。
- 日志禁止记录访问令牌和完整敏感身份信息。
- 所有状态修改带 `request_id`、操作者、原因和前后 revision。

## V1 运营边界

V1 不包含付费货币、PVP、公会和主动技能。任何商业化或新内容实验必须建立新配置版本和变更号，不直接修改 `1.0.0-frozen`。
