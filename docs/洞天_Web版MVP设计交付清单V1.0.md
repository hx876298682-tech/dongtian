# 《洞天》Web版 MVP 设计交付清单 V1.0

## 交付口径

本清单用于判断“设计是否足够进入开发”，不把代码实现、素材制作或线上数据库部署伪装成设计完成。数值基线仍以 `1.0.0-frozen` 为准。

当前实现契约：MVP 使用 `global_single_slot_v1`。炼气/战斗/炼丹/炼器/研究共用一个主动序列，灵田显式种植且不占槽，生产批次自动入库；legacy building job 仅兼容读取/回放。后文“后台生产”若未特别注明，不能理解为当前玩法可以与主动序列并行。

## 进入开发前的内容制作任务

这些不是数值设计缺口，而是内容包和实现资产：

- 补齐名称、图标、立绘、描述和解锁文案。
- 为普通敌人和秘境 Boss 编写行为脚本与表现资源。
- 将规格文档转成实际 JSON 内容包，并生成 manifest。
- 将数据库契约转成迁移脚本和 ORM/SQL schema。
- 将 API 契约转成 OpenAPI 文档和服务端 DTO 校验。
- 将 UX 信息架构转成线框图和视觉设计稿。

## 工程联调验收任务

- 完成 PostgreSQL 行锁/隔离级别压测和事务故障注入。
- 完成 10 并发同 settlement ID、双设备同 revision、时间重叠和回拨测试。
- 完成固定种子回放、战斗日志摘要和离线结算重放。
- 完成配置灰度、版本回滚和历史结算版本兼容。
- 完成异常经济、负库存、重复发奖和掉落偏差报警。

## 明确不纳入 V1

- PVP、公会、社交、主动技能、暴击、套装。
- 付费货币、商城和商业化掉落调整。
- 飞升后的新境界和新的地图/秘境内容。
- 任何未经变更号和全量审计的数值调优。

## 最终设计完成条件

满足以下条件后，MVP 设计可标记为 `design_ready_for_implementation`：

1. 冻结参数表、内容对象、JSON Schema 和数据库字段版本一致。
2. 首发内容包发布时不含可达的 `content_pending` 对象；设计阶段允许保留已登记且有负责人的内容制作字段。
3. 新手引导、单主动序列、灵田种植、战斗、离线、突破和自动入库结算均有明确状态迁移；legacy 队列仅记录迁移/回放边界。
4. 所有写 API 都有幂等键、revision、错误码和事务边界。
5. UX 能展示服务端结算摘要、资源来源、失败原因和下一步行动。
6. 工程验收覆盖并发、回滚、时间边界、配置版本和经济异常。
7. 版本校验、参数 Schema 校验和全量审计通过。

当前判断：设计文档已达到 `design_ready_for_implementation` 的文档条件；素材制作、JSON 落地、数据库迁移和服务端实现属于下一阶段执行，不应反向修改冻结数值。真正发布 MVP 前，必须先清空所有可达的 `content_pending` 对象。
