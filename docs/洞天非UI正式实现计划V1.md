# 《洞天》非 UI 正式实现计划 V1

## 总目标

在重新设计 UI 之前，完成可独立运行、可测试、可回放的游戏服务端与领域运行时。UI 只能调用服务端/领域接口，不能自行计算修为、伤害、掉落、库存或最终结算。

当前玩法基线为 `global_single_slot_v1`：炼气、地图/秘境/高阶、炼丹、炼器、功法研究、法宝研究共用一个主动序列；新序列先结算旧序列；炼丹/炼器自动入库；灵田显式种植且不占槽。legacy building job 仅作历史读取/回放兼容。

## 完成定义

一个模块只有同时满足以下条件才算完成：

- 有版本化配置或明确的参数引用。
- 有领域类型、状态迁移和错误边界。
- 有自动化测试，覆盖成功、失败、重复请求、边界和资源守恒。
- 有可重放的结算摘要或事件日志。
- 不依赖 React UI 才能运行。

## 实施顺序

### P0：配置与领域基础

- `config_version=1.0.0-frozen` manifest、参数索引和内容 Schema。
- 玩家状态、资源、装备、建筑、主行动、保底、随机状态和 settlement 类型。
- 纯函数状态迁移、revision 递增、非负资源和配置版本校验。

### P1：核心玩法引擎

- 闭关/地图/秘境/高阶远征主行动。
- 单主动序列中的炼丹/炼器/功法研究/法宝研究、灵田显式种植成熟和余数结转；不实现可绕过单槽的后台并行生产。
- 普通地图逐场战斗、丹药自动使用、失败冷却、资源和装备掉落。
- 秘境 Boss 状态机、护盾、阶段、眩晕、持续伤害、保底和失败分支。
- 突破、功法研究、法宝星级、装备强化/升品/洗练/觉醒。
- 库存上限、装备出口、溢出、资源预留和资源守恒。

### P2：结算与权威状态

- 离线结算最多 24h、60s 批处理、时间回拨和重叠区间规则。
- settlement ID 幂等、expected revision CAS、失败回滚和摘要哈希。
- PostgreSQL 迁移、玩家行锁、事务边界、配置版本历史引用。
- Redis 只能作为缓存/队列，不能保存不可恢复的最终状态。

### P3：服务端接口与运营可靠性

- `bootstrap`、主行动/序列切换、离线结算、灵田种植、legacy 建筑队列兼容、突破、装备成长和战斗预览 API。
- DTO/Schema 校验、统一错误码、认证边界、审计事件和回放接口。
- 并发、故障注入、重复发奖、负库存、版本回滚和配置灰度测试。
- 结算成功率、重复/过期 revision、经济异常、掉落偏差和 pending 监控指标。

## 当前明确不做

- UI 重构、视觉设计、动效和素材扩充。
- PVP、公会、社交、商城和商业化系统。
- 未经变更号和全量审计的数值调优。

## 最终验收

在没有 React 页面参与的情况下，用固定配置、固定随机种子和测试玩家状态，能够完成：创建状态 -> 生产/远征 -> 战斗/掉落 -> 离线结算 -> 突破/装备成长，并验证重复请求、并发冲突、事务失败和配置版本不一致均不会产生错误资源。
